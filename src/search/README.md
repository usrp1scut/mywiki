# 统一站内搜索

顶部建议和完整结果页共用 `useSiteSearch` 与一个按需启动的 Worker。索引和排名继续来自固定版本的 `@easyops-cn/docusaurus-search-local@0.44.4`，中文分词、转义、高亮与原有标题优先、锚点去重逻辑保持一致。升级该插件时需复核其导出路径并测试中英文查询。

- 空白输入和鼠标悬停不加载索引，输入防抖 120ms。
- 每个搜索入口保留最近一次成功结果（包括空结果），相同关键词重新打开时复用结果，保持键盘选择稳定；缓存按关键词、站点根路径及重试次数区分，未命中时重新查询。关闭时尚未完成的查询仍按原逻辑取消接收。
- Worker 内下载、解压、恢复 Lunr 索引、检索和格式化结果，减少主线程阻塞。没有 Worker 的浏览器使用同一引擎的延迟导入回退。
- `npm run build` 在 Docusaurus 构建后生成并验证 `search-index*.json.gz`。读取时沿用原始索引 URL 的版本哈希；优先压缩文件，兼容服务器已经解压的响应。无 DecompressionStream 或压缩文件尚未部署时回退到 JSON。
- 部署应上传完整 `build/`，包括 `.gz` 与 Worker JS。无需修改 OSS/CDN 的 Content-Encoding 设置；本地开发模式与原插件一样不生成索引，应使用生产构建预览。
- 请求超时、HTTP 错误和 Worker 崩溃均退出加载状态并允许原地重试；失败的引擎初始化不会被永久缓存。React 钩子忽略过期查询或已卸载组件的结果。
- `npm run test:search` 验证压缩完整性、编码兼容、失败重试、并发结果隔离与超时恢复。浏览器验证还应覆盖 IME 输入、键盘选择、触控、空结果、中文查询和实际 Worker 加载。

浏览器回归步骤（先运行生产构建并预览）：

1. 输入 `nginx` 等待建议出现，按 Escape 关闭，再按 ArrowDown 打开。等待超过 120ms 后选中项仍存在，Enter 应进入第一条笔记，而非全部结果页。
2. 修改为中文关键词、清空再输入、在加载完成前关闭再打开，确认结果能正常恢复；失败后点击“重新加载”仍应重新发起查询。
3. 在 390×300、390×360 和桌面矮视口打开搜索，确认整个浮层位于屏幕内，结果列表可以滚动，底部“查看全部结果”始终可见且可点击。正常高度与 200% 文字大小也应检查。视口模拟不等同于手机软键盘或真机触控验证。
