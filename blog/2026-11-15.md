上周的榜单在问“这些 agent 到底归谁管”。本周的问题换了一层：**谁来验收它们的产出？**

答案出现在两个方向。[meta/astryx](https://github.com/meta/astryx) 一周涨 **13,660** 星，是 Meta 把内部用了八年、支撑 13,000+ 应用的设计系统整套以 MIT 开源，README 里反复强调的一句话是“人和 AI 助手按同一套参考来搭”。另一边，[google/elephant-goldfish-model](https://github.com/google/elephant-goldfish-model) 用一只“健忘的金鱼”做评审员——故意不给它前面的对话，只给它文档和源码，专门用来撞出你藏在上下文里的假设。**当生成变得便宜，验收变成瓶颈。**

> 说明：本文依据 [GitHub Trending weekly](https://github.com/trending?since=weekly) 于 2026 年 11 月 15 日抓取的公开页面，结合各仓库 README、GitHub REST API 元数据与最新 release 记录整理。本次页面只解析出 **11 个**热门仓库，合计周增 **61,501** 星，是近几周最短的一份榜单（上周 18 个、98,104 星）。“本周新增 stars”取自 Trending 页面，“总 stars / fork / 未关闭 issue / 创建时间 / 许可证”取自 API 抓取时刻（未关闭 issue 数包含 PR）。需要说明两点：同一天不同时刻抓取 Trending，返回的组合与排序会变化，本文只对这一次快照负责；页面顺序也不是按“本周新增 stars”严格降序排列的（GitHub 用的是自己的热度权重），因此下文 AI 分组内按周增重排。Trending 反映短期关注度，不等同于长期采用率；“为什么变热”是结合项目定位、提交与发布节奏所做的判断，不是平台给出的归因。

## 本周总览

先说结论：

- **第一名是个设计系统，而且它明确为 agent 设计。** astryx 13,660 星，占全榜周增的 22.2%，比第二名高 10%。它不提供新模型、不接管终端，提供的是 150+ 个无障碍组件、主题系统、CLI 和一套“人机共用”的文档约定。这是本周最重要的一条信号：**agent 已经开始反向要求 UI 层的 API 形状。**
- **审阅成了独立的一层。** elephant-goldfish 把“带上下文的作者”和“不带上下文的新评审员”拆成两个角色；Plannotator 用 Inbox 让 agent 把问题挂在那儿、你什么时候有空什么时候答；addyosmani/agent-skills 干脆把 `/review` 做成合并前不可跳过的闸门。三个项目、三种形态、同一个位置。
- **技能仓库进入“版本化治理”阶段。** anthropics/skills 194,685 星配 1,542 个未关闭 issue，本周的动作是许可证迁移收尾（11 月 6 日把 docx/pdf/pptx/xlsx 四个 Office 技能改成 Apache-2.0）与 11 月 14 日的四技能同步更新；addyosmani/agent-skills 打到 v0.6.16；vercel-labs/agent-browser 打出 v0.43.0，把技能做成“跟着 CLI 版本走”的薄壳。上周我在这一栏写“许可证成了暗线”，本周它变成了日常运维。
- **“fork 即部署”让星和 fork 的语义分叉。** [ZhuLinsen/daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis) 72,282 星、**57,490 fork（79.5%）**，只有 34 个未关闭 issue。它的部署方式就是 Fork 本仓库 + 填 Secrets + 跑 GitHub Actions。这种模式里 fork 数是安装量，不是贡献意愿，用它衡量社区活跃度会得出完全相反的结论。
- **非 AI 项目只剩两个半，但都是老面孔回榜。** 11 个位置里，严格非 AI 的只有 sherlock（12,401 星，最新 release 停在 9 月 8 日）和 MuJoCo（1,859 星，4.0.1 于 11 月 11 日发布）；astryx 算跨界——它是设计系统，但把 agent 当成一等用户。
- **本周最猛的增长来自“没有新功能”的项目。** sherlock 一周 12,401 星，而默认分支最近一次提交是 11 月 1 日改 banner 布局；Plannotator 一周 818 星，却是全榜唯一当天发版（v0.28.65，11 月 15 日）的项目。**热度和工程节奏在这份榜单上已经基本脱钩。**

## AI 热门项目

### 1. [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

- **它是做什么的**：开源的 Grok Bot 替代品，形态是“聊天应用里的一队 agent”。侧边栏每个 bot 都是一个真 agent（本机跑 Claude 或 Codex），各有各的人格、模型、云端电脑（VM）和已连接的应用；重要操作走审批卡片。本地优先，transcript 与密钥留在 `~/.openmausbot`。Apache-2.0（`enterprise/` 除外），TypeScript，2026 年 8 月 11 日创建，Electron 打包，macOS（Apple silicon / Intel，签名并公证）、Windows x64、Ubuntu 24.04 四套安装包。
- **为什么这周会热**：本周新增约 **6,413** stars，总 stars 约 **2.29 万**，3,180 个 fork（13.9%），**1,087 个未关闭 issue/PR**，v0.1.158 于 11 月 14 日发布。这是它连续第二周上榜（上周 7,077 星、第 5 名），周增小幅回落但排名上升。issue 密度是全榜最极端的：每千星 47.6 个未关闭 issue，是同榜中位数的四倍。
- **有什么新意**：0.1.158 的关键词是“让 bot 动设置”。你可以直接跟 bot 说改哪个设置，它就改，聊天里给一个 **Undo**；也可以把 MausBot 降级成一个普通 bot。协作侧加了 Rooms 与 teams：在房间里点人名就能跳到他的页面，一个 Chief 能一次编辑最多 40 个 bot 并给每个加规则，负责所有部门的 Chief 会自动获得新部门。还有一个容易被忽略但很实用的动作：**从任意一条消息 fork 一段对话**，试另一个方向而不丢原来那条线。**它的产品直觉是对的——多 agent 系统的瓶颈不是能力，是你没法同时盯住四十个窗口。**

### 2. [anthropics/skills](https://github.com/anthropics/skills)

- **它是做什么的**：Anthropic 官方的 Agent Skills 参考实现。每个技能是一个自包含目录，里面放 `SKILL.md`、脚本和资源，Claude 在需要时动态加载。仓库同时是三个东西：示例技能库（创意设计、开发技术、企业沟通、文档处理）、[Agent Skills 规范](https://agentskills.io)，以及一个技能模板。可以直接作为 Claude Code 的插件市场添加，也有 `document-skills` 与 `example-skills` 两个安装集。
- **为什么这周会热**：本周新增约 **6,220** stars，总 stars 约 **19.47 万**（全榜第二高），2.29 万 fork（11.8%），**1,542 个未关闭 issue**，11 月 14 日刚有一次提交。它是上周“技能与流程类仓库拿走 43.9% 周增”那条观察的延续——这一周它自己就是那条观察的主角。
- **有什么新意**：两个动作连在一起看才有意义。**11 月 6 日**（#2146）把 `docx`、`pdf`、`pptx`、`xlsx` 四个 Office 技能从 source-available 迁到 **Apache-2.0**；**11 月 14 日**（#2217）紧接着同步更新这四个技能。README 现在明确写着“这些技能同样是 Apache-2.0，我们想把它作为复杂技能真实用在生产应用里的参考”。**把支撑商业产品文档能力的核心资产开源，等于承认“技能本身不是护城河”——规范和生态才是。** 顺带一提：19 万星对 1,542 个 issue，说明这个仓库现在承担的是“标准问题答疑处”的角色，而不只是代码库。

### 3. [google/elephant-goldfish-model](https://github.com/google/elephant-goldfish-model)

- **它是做什么的**：一个给 AI 助手的开源插件，做的事是“设计文档的对抗式评审”。三个角色分工很干净：**Elephant** 掌握项目上下文、探索问题、起草规格；**Goldfish** 评审员**看不到前面的对话**，只拿到文档和被引用的源码材料，专门找没说出口的假设、含糊的需求和实现风险；**你** 负责拍架构取舍、批准规格。七个技能可单独使用：brainstorm、draft、resolve、bootstrap、review、review-loop、drift-report。Apache-2.0，2026 年 9 月 13 日创建。
- **为什么这周会热**：本周新增约 **5,539** stars，总 stars 约 **1.93 万**，1,427 个 fork，108 个未关闭 issue，v0.1.1 于 11 月 6 日发布（新增 TRIZ 发明催化评审员、实验性 Cursor / OpenCode V1 / GitHub Copilot 适配器）。它是 `google/` 组织下的项目，但 README 明确标注“**这不是 Google 官方支持的产品**”。
- **有什么新意**：它把“**评审必须换上下文**”写成了硬约束，而不是建议。原文是：Goldfish 评审需要全新的 subagent 上下文，**如果你的 agent 创建不了新 subagent，EGM 会直接停下评审**，而不是降级成同会话自评。这条设计很硬，也很对——同一个上下文里让模型评审自己刚写的东西，几乎必然得到“看起来不错”。它还提供了一个 60 秒的入口：`/egm:egm-review docs/designs/webhooks.md`，直接拿现有设计文档对当前代码做评审；`/egm-drift-report docs/designs/` 则扫描整个目录，报告文档与源码已经漂移到哪里。**“文档漂移”这个说法比“文档过期”准确得多，它描述的是可测量的一种状态。**

### 4. [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)

- **它是做什么的**：给 AI agent 用的浏览器自动化 CLI，本机 Rust 原生二进制。核心循环极简：`snapshot` 把页面拍成一棵紧凑的无障碍树，每个元素带 `@e1` 这样的 ref；agent 点 ref、再读一次页面确认，如此往复。浏览器在命令之间保持打开（后台 daemon 走 CDP），所以每一步都是一次短的 shell 调用。支持 Chrome for Testing、附加已开的 Chrome、Lightpanda / Obscura 引擎、iOS 模拟器里的 Mobile Safari，以及 Browserbase / Browserless / Kernel 等云浏览器。
- **为什么这周会热**：本周新增约 **4,601** stars，总 stars 约 **5.13 万**，3,579 个 fork，579 个未关闭 issue，**v0.43.0 于 11 月 12 日发布**，今天还有推送。对比上周的 1,476 星、第 13 名，本周周增是上周的 **3.1 倍**——同期 v0.41.2 走到 v0.43.0，是这份榜单上少见的“发版带动热度”。
- **有什么新意**：0.43.0 修的是 agent 用浏览器时最真实的两个麻烦。一是 **snapshot hints**：当控件的无障碍名是空的、或者和同一快照里另一个 ref 重名时，hint 会补上图标、图片文件名、`data-testid`、`name`/`id`，以及最近一行或列表项的文本——**这不是让模型更聪明，是让页面更可读**。二是新增 **Modern Web Guidance skill**，能取回 Chrome 对某个任务的现代写法建议，再用 agent-browser 检查实际构建出来的页面。另外它把技能做成了“跟着版本走”的薄壳：安装的技能只是一层 stub，真正内容由 `agent-browser skills get core` 从当前二进制里取，**因此指令永远不会和 CLI 版本脱节**。这个模式值得抄。

### 5. [ZhuLinsen/daily_stock_analysis](https://github.com/ZhuLinsen/daily_stock_analysis)

- **它是做什么的**：LLM 驱动的多市场股票分析系统，覆盖面是 A 股、港股、美股、日股、韩股、台股和 ETF。每天自动跑一遍自选股，产出“决策仪表盘”：核心结论、评分、趋势、买卖点位、风险警报、催化因素、操作检查清单，然后推送到企业微信、飞书、Telegram、Discord、Slack 或邮箱。数据层可插拔（AkShare、Baostock、YFinance 免费源开箱用，Tushare、Longbridge、Pytdx 走 token），模型层兼容 OpenAI、DeepSeek、通义千问、Claude、Gemini、Ollama。还有 Web / 桌面工作台、回测、持仓、15 种内置策略的“Agent 策略问股”。
- **为什么这周会热**：本周新增约 **4,526** stars，总 stars 约 **7.23 万**，**57,490 个 fork（79.5%）**，只有 34 个未关闭 issue，v3.34.0 于 11 月 9 日发布，11 月 14 日一天合了五条修复。README 顶部挂着 arXiv 论文（2608.26990）。
- **有什么新意**：它的部署方式是本周最值得研究的工程细节——**Fork 仓库 → 填 Secrets → 跑 GitHub Actions**，五分钟、零服务器、零成本。79.5% 的 fork 率就是这么来的：每一个 fork 都是一个正在跑的实例，不是一份开发分支。v3.34.0 的内容也很“运维”：可选 FastAPI 安全中间件、定时模式跳过重复启动分析、修 Telegram 消息按 UTF-16 计长、修数据库单例换地址后仍用旧连接、修富途 OpenD 连接的等待边界与失败降级。**一个 72k 星的项目只有 34 个未关闭 issue，说明维护者把 issue 当工单在清，而不是当社区在养。** 顺带一句：它刚加了台股复盘支持，本周还在修韩股退市股票和 Kakao 代码这类细节——多市场不是加个数据源就完事的。

### 6. [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills)

- **它是做什么的**：Addy Osmani 把资深工程师的工作流、质量闸门和惯例打包成 25 个技能，配 9 个斜杠命令，映射到开发的六个阶段：DEFINE（`/spec`）、PLAN（`/plan`）、BUILD（`/build`）、VERIFY（`/test`）、REVIEW（`/review`）、SHIP（`/ship`），另有 `/constraints`、`/webperf`、`/code-simplify`。技能会按上下文自动激活：设计 API 触发 `api-and-interface-design`，写 UI 触发 `frontend-ui-engineering`。可一条命令装进 70+ 个 agent（`npx skills add addyosmani/agent-skills`），也有 Claude Code 插件市场等原生集成。MIT，2026 年 2 月创建。
- **为什么这周会热**：本周新增约 **3,670** stars，总 stars 约 **11.76 万**，1.23 万 fork（10.5%），**只有 124 个未关闭 issue**，11 月 14 日打出 0.6.16。issue 密度全榜最低（每千星 1.1 个），和 OpenMausBot 的 47.6 形成极端对照——一个是有人在认真答疑，一个是有人在认真收工单。
- **有什么新意**：`/build auto` 是本周最值得单独拿出来讲的设计。它允许**批准一次计划，然后连续实现所有任务**：去掉的是人在任务之间的搬运，不是验证——每个任务仍然走 TDD、单独提交，遇到失败或风险步骤会停下。0.6.16 的更新也很有意思：把调试指引对准“粘贴进来的 diff 与堆栈”，以及提醒评审“光读 diff 可能会觉得很快”。**这两条都在处理同一件事：agent 评审时的第一反应是“看起来没问题”，而好的评审框架要主动打断这个反应。**

### 7. [anthropics/claude-quickstarts](https://github.com/anthropics/claude-quickstarts)

- **它是做什么的**：Claude API 的官方起步项目集，每个目录是一个可直接改造的完整应用：客服 agent（带知识库）、财务数据分析（对话式可视化）、Computer Use Demo（容器里控制桌面，已跟到 `computer_toolset_20260801` 的工具集形状）、Computer Use Best Practices（原生 macOS 的参考实现）、Browser Use Demo（Playwright 版）、Browser Toolset（最小 CDP 示例，Python 与 TypeScript 各一份）。
- **为什么这周会热**：本周新增约 **1,794** stars，总 stars 约 **2.10 万**，3,497 个 fork（16.7%），244 个未关闭 issue。最近几次提交的节奏很密：10 月 23 日把 quickstarts 钉在 `anthropic 2.0` / `@anthropic-ai/sdk 1.0` / `ant 2.0`，10 月 29 日加 Sentry autofix 与修 computer-use-demo 读系统 CA 证书，11 月 2 日加 openshell-policy 扩展，11 月 6 日重写“知识 wiki”这个 quickstart。
- **有什么新意**：`computer-use-best-practices` 这一节几乎是一份 agent 可靠性的清单：显式工具定义、正确的图像尺寸与裁剪、prompt caching、服务端压缩、批量工具调用、沙箱 shell、轨迹录制。它明确写着与容器版 Demo 的区别是**直接跑在 macOS 桌面上（“run it in a VM!”）**。而 10 月 29 日那条“读系统的 CA 存储”的修复，是这类项目最容易踩的坑：企业网络里 HTTPS 全靠系统证书链，不读它就一切 403。**quickstart 的价值不在于能跑，而在于它把“能跑”背后的边界一条条写下来了。**

### 8. [backnotprop/plannotator](https://github.com/backnotprop/plannotator)

- **它是做什么的**：一个本地、跑在浏览器里的评审界面，插在 agent 和你之间。agent 提出决策、计划、HTML 产物，或者干完活的时候，应用在浏览器里打开，你直接在页面上标注、评论，然后把反馈一键送回 agent 让它执行。支持 Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、DeepSeek Harness、Pi；代码评审侧接 Git、GitButler、Jujutsu、Perforce、GitHub、GitLab。Apache-2.0。
- **为什么这周会热**：本周新增约 **818** stars（全榜最少），总 stars 约 **1.12 万**，943 个 fork，235 个未关闭 issue，**v0.28.65 于 11 月 15 日发布**——它是全榜唯一在抓取当天发版的项目。周增最少但排名进榜，说明这份榜单的长度只有 11 个，长尾也被纳入了。
- **有什么新意**：新东西是 **Plannotator Inbox**：一个本地窗口，agent 把消息、问题、文件、待审内容留在那里，然后继续干活；你有空时点一下回答问题、标注文件、按发送，回复会回到当初提问的那个会话。关键设计是**“不挂起任何 agent 会话”**。Claude Code、Pi、OpenCode 通过插件接入，其他 agent 走 `plannotator inbox mcp`。**这是一个很小但很对的转向：过去是人等 agent，现在让 agent 等人，而且等人时不占着会话。** 多 agent 并行的真正成本从来不是算力，是人的注意力切换。

## 非 AI 与泛基础设施

### 1. [meta/astryx](https://github.com/meta/astryx)

- **它是做什么的**：Meta 的设计系统开源版。它过去八年在 Meta 内部长大，是公司里**使用最广、体量最大**的设计系统，支撑 13,000+ 应用；现在整套以 MIT 发布：150+ 个无障碍组件、品牌级主题、深色模式、现成模板和一个 CLI。技术上是 React 19+ 与 StyleX，但 StyleX 对使用者不可见——直接 import 预构建 CSS，用 `className` 配 Tailwind、CSS Modules 或原生 CSS 都行，不需要构建插件、PostCSS 或 Babel 配置。七个内置主题（neutral、butter、chocolate、matcha、stone、gothic、y2k），另有 `swizzle` 可以把组件源码整个弹出到你的项目里。
- **为什么这周会热**：本周新增约 **13,660** stars（全榜第一，占 22.2%），总 stars 约 **2.82 万**，2,196 个 fork（7.8%），668 个未关闭 issue，`v0.7.16` 于 11 月 14 日发布，今天仍有提交。仓库 2026 年 1 月 9 日创建，目前状态是 **Beta**。
- **有什么新意**：它的差异化不在组件数量，而在一句很少见的产品原则：**“One system for humans and AI.”** API、约定、文档和 CLI 是一起设计的，人和 AI 助手从同一份参考出发；README 里那句“每一条让 Astryx 对 AI 更容易的改动，也让它对人类更容易”，是本周最值得抄的一句话。具体落地上，它的 CLI 被设计成 agent 可调用的形状（`astryx docs global/project-global-or-both`、`astryx component --list`），并建议在 `package.json` 里加一个 `npm run astryx --` 脚本，理由写得很直白：**避免 AI 助手或新同事直接调 CLI 时的路径错误**。它还把约定写成可评审的 wiki 条目（API Conventions、Design Conventions、Component Lifecycle、Blog Review Rubric），要求 PR 前先读对应的评分标准。**设计系统第一次开始为“读者是模型”这件事做工程决策。**

#### 为什么这一节只有三个项目

11 个位次里，严格意义上的非 AI 项目只剩两个（sherlock、MuJoCo），加上跨界的 astryx 才凑到三个。这一周不是非 AI 项目变少了，而是**AI 相关的位次被“技能与评审”这类中间层占满**——它们不产出能力，产出的是流程、界面和闸门。为避免填充弱项目，这里只保留三个代表性仓库；astryx 虽属设计系统，但它的核心卖点就是服务 agent，所以放在这一节并单列说明。

### 2. [sherlock-project/sherlock](https://github.com/sherlock-project/sherlock)

- **它是做什么的**：老牌 OSINT 工具，用一个用户名去 **400+ 个社交网络**上查有没有这个账号，输出一份命中列表。Python，MIT，2018 年 12 月创建。安装方式很省事：`pipx install sherlock-project`、`docker run -it --rm sherlock/sherlock` 或 `dnf`；README 顶部有一条警告，说第三方维护的 ParrotOS 与 Ubuntu 24.04 包**已损坏**，建议改用 `uv`/`pipx`/`pip` 或 Docker。
- **为什么这周会热**：本周新增约 **12,401** stars（第二名），总 stars 约 **11.19 万**，1.29 万 fork，415 个未关闭 issue。但工程侧几乎没动静：**最新 release 是 9 月 8 日的 v0.16.2**，当时的发布说明只有一句“距上一个版本已经很久了，中间做了些小改动”；默认分支最近一次提交是 **11 月 1 日改 banner 布局**。
- **有什么新意**：本周没有新功能。它上榜本身就是结论：**一个 2018 年的、八年没换过形态的账号检索工具，在没有发版的情况下拿到全榜第二。** 放在本周的语境里看就更清楚——旁边是 agent-browser（给 agent 一个浏览器）、Plannotator（给 agent 一个评审窗口），sherlock 是“给 agent 或人一个跨站点的身份核查器”。它提醒我们，Trending 榜单衡量的从来不只是工程增量，还有**这一周大家的注意力在补哪块基础设施**。

### 3. [google-deepmind/mujoco](https://github.com/google-deepmind/mujoco)

- **它是做什么的**：DeepMind 的通用物理仿真器，做的是带接触的多关节动力学，是机器人与强化学习领域的标准工具之一。C++，Apache-2.0，2021 年 8 月开源。
- **为什么这周会热**：本周新增约 **1,859** stars，总 stars 约 **1.80 万**，2,204 个 fork，415 个未关闭 issue，**4.0.1 于 11 月 11 日发布**，11 月 13 日还有推送。周增不算高，但它是本周唯一一个“大版本刚落地”的成熟科学计算项目。
- **有什么新意**：4.0.1 是个维护版本，但两处改动值得记：编译器侧新增 `mjs_getInStringVec`，可以按下标从 `mjStringVec` 里读条目；Python 绑定侧把 **MuJoCo Studio Web Viewer 在 Windows 上打开**了（`mujoco-studio --gfx=web` 与 `mujoco.studio.launch_web`）。**仿真器这种项目，热度通常来自下游**——机器人、具身智能的每一轮投入都会回流成这里的 star。

## 技术趋势分析

#### 趋势一：验收层正在从流程里长成产品

把本周三个 AI 项目叠在一起看，位置完全重合：elephant-goldfish 负责“设计文档有没有漏洞”，Plannotator 负责“人怎么把意见送回 agent”，agent-skills 负责“合并前必须过哪几道闸”。三者都不生成代码。

这解释了为什么它们的形态差异这么大，功能却不重叠——**验收不是一个功能点，是一条链路**：产出 → 换上下文重读 → 人标注 → 反馈回会话 → 硬闸门。上周的榜单在抢入口（谁接管终端），本周在抢出口（谁负责说不）。

#### 趋势二：技能从“内容”变成“跟着版本走的薄壳”

agent-browser 的做法值得单独抄一遍：安装到 agent 里的技能只是一层 stub，真正内容由 `agent-browser skills get core` 从当前二进制里取。这样**指令永远不会落后于 CLI 版本**。

对比 anthropics/skills 的路径——技能就是仓库里的文件，靠发布节奏同步（11 月 6 日改许可证，11 月 14 日更新四个 Office 技能）。两种模式各有代价：薄壳要维护一个 `skills get` 子命令，仓库要维护发布纪律。但两边指向同一件事：**技能已经开始有版本兼容问题，而大家还在用“复制一份 prompt”的方式分发它。**

#### 趋势三：agent 的接口正在标准化到三层

本周榜单里，agent 被赋予的外部能力集中在三个标准接口上：

- **浏览器**：agent-browser 的 `snapshot` + refs 模型，把页面压成可读文本而不是截图。
- **桌面**：claude-quickstarts 的 computer-use-best-practices 明确要求在 VM 里跑原生 macOS，并给出显式工具定义、图像裁剪、prompt caching 这套可靠性清单。
- **机器**：OpenMausBot 给每个 bot 一台云端 VM，重要操作走审批卡片。

三层接口的共同点不是能力，是**可观察性**：ref 可复查、轨迹可录制、审批可撤回。

#### 趋势四：设计系统第一次把模型当读者

astryx 的 CLI 文档里写着“避免 AI 助手直接调 CLI 时出现路径错误”，这件事的性质比它听上去重要——**它意味着 UI 库的 API 设计要考虑第二个消费方**：不是“人类能不能记住”，而是“模型能不能从文档里稳定推出正确调用”。它给出的四条原则里，“Guidance over enforcement”（给能力，不给跟你作对的护栏）和“Earned by measurement”（约定要靠测试赢得，不靠断言）都更像是写给 agent 的接口规范。

#### 趋势五：星数的通胀已经到了要看分母的程度

本周这组数字放在一起很刺眼：anthropics/skills 19.5 万星 / 1,542 个未关闭 issue；daily_stock_analysis 7.2 万星 / **79.5% fork 率** / 34 个未关闭 issue；addyosmani/agent-skills 11.8 万星 / 124 个未关闭 issue；OpenMausBot 2.3 万星 / 1,087 个未关闭 issue。

同一份榜单里，issue 密度差了 40 倍，fork 率差了 10 倍。**星数只能说明这一周有多少人第一次看见它；fork 率、issue 密度、最后推送时间才说明它现在被怎么用。** 尤其是“fork 即部署”这种模式普及之后，fork 数已经从“贡献意愿”变成了“安装量”，两个语义不能再用同一个数字表达。

## 本周最值得关注的新鲜点

1. **Meta 把内部最大的设计系统整套 MIT 开源，而且卖点是人机共用。** 13,000+ 应用的存量、八年演化、150+ 组件，一次性放出来，这在开源史上不常见。
2. **“评审必须换上下文”被写成了硬约束。** elephant-goldfish 在无法创建新 subagent 时直接停止评审，而不是退化成自评——这个“宁可停下也不降级”的选择，是本周工程质量最高的一处判断。
3. **Plannotator Inbox 把“人等 agent”翻成“agent 等人”，且不挂起会话。** 多 agent 并行的真实瓶颈是人的注意力，这条设计正面回应了它。
4. **daily_stock_analysis 的 79.5% fork 率是一个新指标。** Fork 即部署 × GitHub Actions 零成本，让 fork 数变成安装量；这也解释了为什么 72k 星的项目只有 34 个未关闭 issue。
5. **agent-browser 的“技能跟着二进制版本走”。** 用一个 `skills get` 子命令解决技能与 CLI 脱节的问题，比任何 prompt 工程技巧都更接近可维护性。
6. **这份榜单只有 11 个。** 上周 18 个、周增 98,104 星，本周 11 个、61,501 星。榜长变了，所以“第几名”的横向比较要打折——**排名是相对的，周增才是绝对的。**

## 结语

这一周没有一个项目在比模型更聪明。第一名把内部设计系统开源并为人机共用重写约定，第二名是个八年没发版的用户名检索器，AI 侧的三强全都在做“怎么验收”而不是“怎么生成”。

如果要挑一条留给下周看，我会选 elephant-goldfish 的那句硬规则：**评审员必须没有上下文，创建不了新上下文就停下。** 它承认了一件很多工具不愿意承认的事——同一个会话里的自我检查，价值接近于零。
