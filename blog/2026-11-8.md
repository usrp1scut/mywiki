上周的榜单在问“为什么机器做出来的东西还是像机器做的”。本周换了问题：**这些 agent 到底归谁管？**

答案先出现在第一名上。[t3code](https://github.com/pingdotgg/t3code) 一周涨 **17,100** 星，做的不是更聪明的 agent，而是一个把本机所有 agent 统一接管的控制台；它的 README 里专门有一节叫 “Wait, what are you selling me?”，回答是 Nothing。另一半注意力落在许可证和组织上，而不是功能上——一个官方技能仓库改了许可证，一个开源 PR 审查器被捐给了社区。**当执行能力不再稀缺，稀缺的是入口、权限和归属。**

<!-- truncate -->

> 说明：本文依据 [GitHub Trending weekly](https://github.com/trending?since=weekly) 于 2026 年 11 月 8 日抓取的公开页面，结合各仓库 README、GitHub REST API 元数据与最新 release 记录整理。本次页面解析出 **18 个**热门仓库，合计周增 **98,104** 星；“本周新增 stars”取自 Trending 页面，“总 stars / fork / 未关闭 issue / 创建时间 / 许可证”取自 API 抓取时刻（未关闭 issue 数包含 PR）。需要说明一点：同一天不同时刻抓取 Trending，返回的组合与排序会变化，因此本文只对这一次快照负责。Trending 反映短期关注度，不等同于长期采用率；“为什么变热”是结合项目定位、周增量、提交与发布节奏所做的判断，不是平台给出的归因。

## 本周总览

先说结论：

- **第一名是控制面，不是模型能力。** t3code 17,100 星，占全榜周增的 17.4%，比第二名高出 77%。它接管本机已经装好的 Claude Code、Codex、Cursor、Grok Build、OpenCode、Antigravity、fx，然后从手机、浏览器、桌面端统一操作。当 provider 数量稳定下来，大家抢的是“入口”这一层。
- **许可证成了本周的暗线。** Anthropic 把 `docx`、`pdf`、`pptx`、`xlsx` 四个 Office 技能从 source-available 改成 Apache-2.0；Qodo 把 PR-Agent 捐给社区、迁到独立 org、准备再捐给基金会；OpenMausBot 把 `enterprise/` 拆成 source-available，删掉该目录即开源版。上周的答案是“核心开源、托管收费”，本周的答案变成了“许可证与组织”。
- **配置的信任边界在被切开。** pr-agent v0.50.0 明确禁止仓库里的 `.pr_agent.toml` 覆盖 GitHub 节流、重试、身份与调用次数；OpenMausBot 新版把所有对外入口默认关掉，用 12 位配对码；agent-browser 把「state 文件里的 token 是明文」写进 README，并给出加密环境变量。
- **技能与流程类仓库拿走 43.9% 的周增。** 八个技能/方法论仓库合计 43,110 星（mattpocock/skills、impeccable、hallmark、CCGS、superpowers、spec-kit、anthropics/skills、jakubkrehel/skills）。其中设计向三个合计 16,185 星，占 16.5%，这是“反 AI slop”连续第二周上榜。
- **非 AI 项目回来了，但身份变了。** 18 个位置里有 4 个非 AI（Scrapling、ziwei-doushu、worktrunk、Hyprland），其中三个是“被 agent 调用”的基础设施。严格意义上与 agent 无关的只有 Hyprland 一个。
- **星数通胀到了需要重新校准的程度。** mattpocock/skills 31.8 万星只有 553 次提交；Kronos 停更七个月本周仍涨 2,937；Claude-Code-Game-Studios 停更三周涨 5,719；Hallmark 本周只修 bug 涨 6,624。周增只能看注意力，fork 率、issue 密度、最后推送时间才是维护实况。

## AI 热门项目

### 1. [pingdotgg/t3code](https://github.com/pingdotgg/t3code)

- **它是做什么的**：一个“agent harness 控制面”。本机装着的 Claude Code、Codex、Cursor、Grok Build、OpenCode、Google Antigravity、fx，只要登录过，它都能接管，然后通过 iOS / Android 应用、Web、Electron 桌面端统一操作：远程访问、权限模式、多账号、通过 MCP 让外部 agent 接进来、源码管理集成、后台服务 `t3 service install`。分发面铺得很全：winget、scoop、Homebrew cask、`.deb`、AUR、`npx t3@latest`。MIT，TypeScript，2026 年 2 月创建，9,064 次提交。
- **为什么这周会热**：本周新增约 **1.71 万** stars（全榜第一，是第二名的 1.77 倍），总 stars 约 **5.14 万**，9,895 个 fork（19.2%），v0.1.7 于 11 月 4 日发布。README 里那句 “Wait, what are you selling me?” 是本周传播力最强的一段：回答是 **Nothing**，理由是“我们想要最好的 agent 开发体验，现有方案都没达到我们的标准”，并且明确说“如果我们走错方向，你应该拥有 fork 出自己想要的那个编辑器所需的一切”。
- **有什么新意**：别把它当成又一个 GUI。它真正下注的是**远程与多 provider 的兼容层**——每个 provider 的登录、hooks、权限模式都不一样，要统一就得一家一家啃。代价也写在同一页上：**5,809 个未关闭 issue/PR 对 5.14 万星，平均每 8.9 个 star 一个**，而 README 自己写着“我们处于非常非常早期的阶段，准备好遇到 bug”“基本不接受贡献，大功能一律不做”。**一个不收费、不接受贡献、issue 堆到五千多的项目能拿第一，说明这个品类的需求远大于供给。**

### 2. [mattpocock/skills](https://github.com/mattpocock/skills)

- **它是做什么的**：Matt Pocock 把自己 `.agents` 目录里每天在用的技能直出。README 的定位很清楚：**小而可组合、随便改、任何模型都能用**，并且直接反对 GSD、BMAD、Spec-Kit 这类“接管流程”的方案——理由是它们拿走了你的控制权，出问题时很难定位是流程的 bug 还是你的 bug。安装渠道覆盖 Claude Code 插件市场、Codex marketplace、Copilot CLI 与 VS Code、Gemini CLI、`npx skills`。装完跑一次 `/setup-matt-pocock-skills`，它会问你用哪个 issue tracker、打什么标签、文档放哪。技能分工程与生产力两组：`grill-me` / `grill-with-docs`（被追问到设计树的每个分支都有答案）、`handoff`（把会话压成交接文档）、`teach`、`to-questionnaire`、`wait-what`、`pr`、`wizard`。MIT，以 Shell 为主。
- **为什么这周会热**：本周新增约 **9,664** stars，总 stars 约 **31.8 万**（全榜第二高），2.66 万 fork（8.4%），219 个未关闭 issue，v1.3.2 于 10 月 29 日发布。但全部内容只有 **553 次提交**——31.8 万星对 553 次提交，这是本周通胀最极端的一组数字。真正的推力是**它和同榜的 spec-kit 形成了公开对照**：一个说“流程归我”，一个说“零件归你”，两种主张在同一周被同时投票。
- **有什么新意**：它把“沟通失败”当成第一故障模式，而不是把“模型不够聪明”当成第一故障模式。`grilling` 是那套可复用的追问原语，被 `grill-me`、`triage`、`wayfinder` 反复调用；`writing-for-agents` 则专门讲“写给 agent 看的文档”该怎么写。最值得记的是 `wizard`：**生成一个交互式 bash 向导，把只有人才能做的事（开基础设施、配 CI secret、走第三方控制台、做一次性迁移）一步步交回给人。** 这条边界画得比技能数量重要——它承认有些步骤 agent 不该代劳。

### 3. [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

- **它是做什么的**：给编码 agent 的“设计词汇表”。24 个命令分四组：steer（bolder / quieter / distill / colorize / typeset / layout / animate / delight / overdrive）、review（critique 打分、audit 出 P0–P3 报告）、finish（polish / harden / clarify / adapt / optimize / onboard）、plan（shape / init / document / extract）。`critique` 与 `audit` 是 **62 条确定性规则，零 LLM、零 API key**。Apache-2.0，Rust CLI，支持 20 多个 harness。
- **为什么这周会热**：本周新增约 **7,623** stars，总 stars 约 **10.56 万**，6,277 个 fork，71 个未关闭 issue，`cli-v4.8.1` 就在今天（11 月 8 日）发布。连续第三周在榜，周增比上周的 12,031 回落，但仍是设计向第一。
- **有什么新意**：4.8.1 是一份纯工程修复的 changelog，但恰好暴露了这个品类的真实瓶颈：`detect` 现在会扫 `.mjs` / `.cjs`；页面狂刷 console 或 network 事件不再让进程无限增长；百分号转义后接非 ASCII 字符不再让 `detect` 崩；Windows 上 `check` 不再每次都报有更新；交互选择器里选中的 harness 即使已装了别的也能装上。**“品味检查器”的难点已经不在规则，而在把它指向一个真实页面时的资源、编码与平台边界。** Engine 0.1.19 同时修了对比度与背景判定。

### 4. [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

- **它是做什么的**：跨会话的记忆压缩层。hook 捕获 agent 每次会话里的工具使用观察，用 AI 压成语义摘要，再把相关内容注入未来会话；通过 MCP 暴露检索工具，记忆检索分层披露并显示 token 成本。支持 Claude Code、OpenCode、T3 Code、Antigravity、DeepSeek Harness、OpenClaw 等十来个宿主。Apache-2.0，TypeScript，2025 年 8 月创建。
- **为什么这周会热**：本周新增约 **7,482** stars，总 stars 约 **11.46 万**，9,935 个 fork，87 个未关闭 issue，v15.12.0 于 11 月 7 日发布。它维持着日更节奏，本周的版本又把另一个上榜项目（T3 Code）的集成路径跟上。
- **有什么新意**：**图片默认保留，但明确不送进模型。** v15.12.0 把 agent 读过或生成的截图保留下来并关联到当轮观察，同时把 image inference 保持关闭；截图改为在本机转码，每次 20 秒、排队执行，统一存成有损 WebP 以控制体积；My Work 里加了带键盘导航的图库；托管侧每位 owner 在 cmem.ai 有 25 GiB 图片配额。上周我在这一栏写的是“隐私默认值从本地翻到了云端”，这周它做了个反向修正：**记忆可以存图，但不能把图送出去推理。**

### 5. [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot)

- **它是做什么的**：开源的 Grok Bot 替代品，形态是“聊天应用里的一队 agent”。侧边栏每个 bot 都是一个真 agent（本机 `claude` / `codex` / `grok` CLI），各有各的人格、模型、云 Linux 桌面或隔离本地 VM，还能通过 Composio 接 500+ 应用；重要操作走审批卡片。本地优先：一个跑在 `127.0.0.1` 的小 harness server 管所有 agent 进程，transcript 与密钥都在 `~/.openmausbot`，不经云端。Apache-2.0（`enterprise/` 除外），TypeScript，2026 年 8 月创建。
- **为什么这周会热**：本周新增约 **7,077** stars，总 stars 约 **1.72 万**，2,423 个 fork（14.1%），v0.1.148 于 11 月 7 日发布。2026 年的七周里，四个闭源个人 agent 产品（Grok Bot、Meta Muse、OpenAI dots、Manus Cue）把这个形态定了型：一个聊天窗口、一队有自己电脑的 agent、模型与数据都在厂商那一侧。开源替代自然承接了不满，README 干脆把五个产品的对照表列出来。
- **有什么新意**：新版把“连接”这件事的默认值改成了全部关闭——README 原话是 **Nothing starts by itself**，每种进入这台电脑的方式各有一个开关，Tailscale 和手机链路不打开就永远不启动，只连服务器的桌面端一个都不开；配对统一成 12 位码，公网 `http://` 直接拒绝并告诉你该怎么做。另外两处细节值得记：首页警告“本项目没有任何代币”，任何同名币都与作者无关；许可证把 `enterprise/` 单独 source-available。**“开源核心 + 企业目录”这种拆分，比“开源核心 + 托管收费”更靠前一步——它把商业边界画在了目录上。**

### 6. [Nutlope/hallmark](https://github.com/Nutlope/hallmark)

- **它是做什么的**：给 Claude Code、Codex、Cursor、OpenCode 用的设计技能，目标是“拒绝看起来像 AI 生成的页面”。三级 gate：Floor 永不发布（对比度、焦点态、reduced motion、编造事实、手机上排崩的布局）、Reflex 是模型默认会犯但可按记录推翻的毛病、Finish 只是手艺细节不阻塞上线，最后再加一个从全新上下文进入的评审员。内置开放授权照片、按主题挑选并署名，能截取真实产品页面。
- **为什么这周会热**：本周新增约 **6,624** stars，总 stars 约 **5.04 万**，2,671 个 fork（5.3%），45 个未关闭 issue，最后一次推送是 11 月 5 日。上周它是周增第一（12,062），本周回落到第六。看提交记录就知道原因：**这一周全是修 bug**——主题文件的 CRLF 换行、imagegen 响应计数、`sloppint` 对点目录的处理、1440 宽度渲染、某个主题的 id、app scaffold 命令、draw job 的同义词。
- **有什么新意**：本周没有新功能可讲，但这组数字本身是个结论：**一个成熟到“只修 bug 也能涨 6,624 星”的技能，和上周那个靠 v2 大版本冲榜的技能，已经不是同一种东西了。** fork 率连续两周 5.3%，用法固定为“装上就用”。它和 impeccable 的分工也没变：一个靠三级 gate 和评审员，一个靠 62 条确定性规则。

### 7. [Donchitos/Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)

- **它是做什么的**：把一次 Claude Code 会话变成一家游戏工作室。49 个 agent 分三层——导演（创意、技术、制作人）、部门主管（game designer、lead programmer、art director、audio、narrative、QA、release、localization）、专家（gameplay / engine / AI / network / tools / UI 程序、关卡、经济、技术美术、音效、编剧、world builder、UX、性能、DevOps、安全、QA、无障碍、live-ops）；74 个斜杠命令覆盖 `/start` 到 `/launch-checklist`；12 个 hook 在提交、推送、资源变更时做校验；13 条按路径生效的编码规范；39 份文档模板；Godot 4 / Unity / UE5 各一套引擎专家。MIT，Shell 为主，2026 年 2 月创建，**全部只有 42 次提交**。
- **为什么这周会热**：本周新增约 **5,719** stars，总 stars 约 **3.66 万**，4,834 个 fork（13.2%），95 个未关闭 issue，v1.2.0 于 **10 月 19 日**发布——此后三周没有新提交。它上榜不是靠更新，是靠“组织架构”这个比喻被转发。
- **有什么新意**：README 里有一段自测，是本周最诚实的一段项目自述：同一份 brief 用不同 `modes.rigor` 跑出四款游戏，`standard` 在第一行游戏代码之前写了 **30 份文档**、花了 58 分钟，`minimal` 只写 1 份、0 分钟，四款都能跑、都测过；然后两位盲评加一次人类试玩，把 `standard` 排在**最后**——多出来的 29 份文档买到的是可追溯性，不是更好的游戏。它还给自己定了一条硬规则：任何改动玩家可见内容的故事，必须启动游戏、观察、把截图存进 `production/qa/evidence/`，**“解析通过不算跑过”**。

### 8. [obra/superpowers](https://github.com/obra/superpowers)

- **它是做什么的**：一套给编码 agent 的完整开发方法论：先问清你要做什么，把 spec 切成短到能读完的块给你签字，再生成一份“连没品味、没判断力、没有项目上下文、还讨厌测试的初级工程师都能照着做”的实施计划，强调真红绿 TDD、YAGNI、DRY；你说 go 之后进入 subagent-driven development，agent 逐任务推进并互相 review。MIT，Shell 为主，2025 年 10 月创建。
- **为什么这周会热**：本周新增约 **4,466** stars，总 stars 约 **31.4 万**，2.80 万 fork（8.9%），342 个未关闭 issue，v7.0.2 于 11 月 3 日发布。它已经进了 Anthropic 与 OpenAI 两家的官方插件市场，属于“底盘型”增长。
- **有什么新意**：v7.0.2 全部在调 **brainstorming 的提问方式**：只在“答案会改变要建什么、而且现有信息没答过”时才提问，其余情况直接陈述判断供你纠正；如果用户没说 why，第一件事就是问 why，且不给示例答案；当它能说出选项时，把选项连同推荐一起摆出来。它还给了一组 8/8 的对照：在 Ctrl+K 被两个功能同时占用的场景里，7.0.1 **8 次都发现了冲突，但 8 次都只问了一句“选哪个”**；7.0.2 **8 次都给出选项并附推荐**。**“少问、问对、把选择摆成选项”是可以被版本化调优的，这条比任何 prompt 技巧都更接近工程。**

### 9. [github/spec-kit](https://github.com/github/spec-kit)

- **它是做什么的**：GitHub 官方的 SDD（spec-driven development）工具包，`uv tool install specify-cli --from git+...` 之后 `specify init` 起步，把“先写规格、再让 agent 按规格实现”固化成命令与模板，支持 Copilot、Claude、Gemini 等多种集成。
- **为什么这周会热**：本周新增约 **4,280** stars，总 stars 约 **14.85 万**，1.33 万 fork，205 个未关闭 issue，v1.3.2 于 11 月 6 日发布。它是 2025 年 8 月创建的项目，一年后仍在稳定吸量，属于“官方流程”的基本盘。
- **有什么新意**：v1.3.2 本身是一次例行发版（社区扩展目录加 Assure、deja-vu 会话回忆、Illustrate；文档对齐 Copilot skills；CI 矩阵加 Python 3.15；`integrations` 卸载时刷新 manifest hash）。值得看的是方向：**它在长成一个扩展市场**——第三方工作流以扩展形式进目录，官方只维护骨架。这和 mattpocock/skills 的“拒绝接管流程”正好相反，两条路线这一周同时上榜，说明分歧还没分出胜负。

### 10. [shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)

- **为什么这周会热**：本周新增约 **2,937** stars，总 stars 约 **4.73 万**，7,811 个 fork（16.5%），297 个未关闭 issue。而它**最后一次推送是 2026 年 4 月 13 日**——七个月没有代码更新，本周仍进榜。在一个人人写 agent 的榜单里，“金融时序基础模型”是稀缺题材，这是它被重新翻出来的原因。

### 12. [The-PR-Agent/pr-agent](https://github.com/The-PR-Agent/pr-agent)

### 14. [jakubkrehel/skills](https://github.com/jakubkrehel/skills)

### 15. [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)

### 17. [max-sixty/worktrunk](https://github.com/max-sixty/worktrunk)

- **它是做什么的**：管 git worktree 的 CLI，为“同时跑多个 agent”设计。三条核心命令把 worktree 用得和分支一样简单：`wt switch feat`（切过去）、`wt switch -c -x claude feat`（新建并直接把 Claude 起在那个目录里）、`wt remove`（连 worktree 带分支一次清掉），`wt list` 带状态。往上还有一堆实用件：create / pre-merge / post-merge 等 hook、用 diff 生成 commit message、squash/rebase/merge 加清理一条命令、带 CI 状态与 PR 预览的交互选择器、`wt switch pr:123` 直接切到某个 PR 的分支、`hash_port` 给每个 worktree 分配独立端口跑 dev server，以及在 APFS / btrfs / XFS 上用 copy-on-write **共享 `target/`、`node_modules`**，让十个 worktree 不用各建一遍。Rust，MIT 或 Apache-2.0，5,285 次提交。
- **为什么这周会热**：本周新增约 **2,292** stars，总 stars 约 **1.20 万**，465 个 fork，50 个未关闭 issue，v0.81.0 于 10 月 20 日发布。理由很直接：一个 agent 能连续跑几小时之后，人自然会同时开 5 到 10 个，而 `git worktree` 的原生 UX 要求你把分支名敲三遍。
- **有什么新意**：**它解决的是“多开”的文件系统成本，而不是命令数量。** CoW 共享构建缓存这一条，比再多几个子命令有用得多——十个 worktree 各自 `npm install` 一遍，磁盘和时间的代价比记不住命令大得多。v0.81.0 让 hooks 能继承 stdin 做交互确认（`gum confirm 'trust this worktree?'`），代价是 hooks 不再通过 stdin 收 JSON 上下文，属于要读 changelog 才能避开的破坏性变更。

### 18. [hyprwm/Hyprland](https://github.com/hyprwm/Hyprland)

- **为什么这周会热**：本周新增约 **1,436** stars，总 stars 约 **4.05 万**，2,165 个 fork，197 个未关闭 issue，v0.57.1 于 11 月 3 日发布。周增不算高，但在一个 18 个位置里 14 个是 agent 工具的榜单上，它代表另一条技术线：图形栈、输入、窗口管理。

#### 为什么这周非 AI 回来了

上周是 0 个，本周 4 个，但结构变了：Scrapling 和 worktrunk 都是**被 agent 调用**的基础设施（一个提供网页输入，一个提供并行工作区），ziwei-doushu 是内容与数据仓库，只有 Hyprland 与 agent 完全无关。所以准确的说法不是“非 AI 回来了”，而是**基础设施开始以“agent 的配件”身份回到榜单**。

另一面是容量：18 个位置里 14 个仍是 AI 相关，AI 项目拿走 80,758 星（82.3%）。这周没有一个推理引擎、数据库或编译器项目进榜——不是它们不活跃，是这一周的注意力被“控制台 + 技能 + 治理”这三件事占满了。

## 技术趋势分析

**一、当 provider 稳定下来，竞争就转到入口。** t3code 17,100 星、占全榜 17.4%，卖的是一层兼容与远程：七个 provider 各自登录、各自 hooks、各自权限模式，统一起来就是护城河。这和上周 claude-mem 的记忆层、T3 Code 的首次上榜是同一条线，本周只是把它坐实了——**agent 越多，管 agent 的那一层越值钱。**

**二、开源与商业的分界线，从“托管”挪到了“许可证与组织”。** 三件事在同一周发生：Anthropic 把四个 Office 技能改成 Apache-2.0（把原来的收费护城河让出去）；Qodo 把 pr-agent 捐给社区并准备捐给基金会（把治理权让出去）；OpenMausBot 把 `enterprise/` 划成 source-available（把商业边界画在目录上）。方向不同，问题相同：**哪一部分必须开放才能换来分发，哪一部分必须留住才能活下去。** 上周的答案是托管，本周的答案是许可证文本和组织归属。

**三、配置的信任边界正在被切开。** pr-agent v0.50.0 把节流、重试、身份、调用次数这些“能被仓库影响的行为”全部收回到宿主配置；OpenMausBot 把所有对外入口默认关掉、只认 12 位配对码；agent-browser 把 state 文件里的明文 token 写进 README 并给加密开关。共同点是：**agent 现在跑在别人的仓库、别人的 PR、别人的网页上，“谁能改什么”就是攻击面。** 这个判断上周还只出现在安全类项目里，本周进了通用工具。

**四、判断力继续被拆成规则、提问和证据。** Impeccable 用 62 条确定性规则判“AI 味”；superpowers 7.0.2 用 8/8 的对照调“该不该问、怎么问”；CCGS 用 `modes.rigor` 的盲评承认“30 份文档买到的是可追溯性，不是更好的游戏”；jakubkrehel 的 `afk` 把“用户不在时做什么”交回给仓库文档。四条路都在回答同一件事：**模型不该被期待有判断力，判断力应该被写成可执行、可核对的东西。**

**五、token 成本进了工具设计的第一屏。** agent-browser 的 `--if-changed`、`--delta`、按需加载单个 skill reference；Scrapling 的 MCP 先用 CSS 收窄再剥注入；claude-mem 的图默认存但不推理。**“少读一点”从优化项变成了产品特性**——这在一个上下文仍然按 token 计价的年份里，是最实际的一类创新。

**六、星数已经没有区分度，需要三个指标校正。** 本周的对照很鲜明：mattpocock/skills 31.8 万星只有 553 次提交；Kronos 停更七个月仍涨 2,937；CCGS 停更三周涨 5,719；Hallmark 只修 bug 涨 6,624。反过来，Scrapling 9.9 万星只有 15 个 issue，ziwei-doushu 1.68 万星有 19.4% 的 fork 率，t3code 5.14 万星堆了 5,809 个未关闭 issue/PR。判断方式不变：**周增看注意力，fork 率看是否真被改造，issue 密度看维护压力与期待落差，最后推送时间看项目是否还活着。**

## 本周最值得关注的新鲜点

- **Anthropic 把 Office 四件套改成 Apache-2.0**：`docx`、`pdf`、`pptx`、`xlsx` 不再是 source-available。技能生态里最赚钱的那块被官方自己打开了。
- **pr-agent v0.50.0 的权限收回**：仓库级 `.pr_agent.toml` 不能再覆盖节流、重试、身份与调用次数。agent 跑在别人仓库上时，配置就是攻击面。
- **CCGS 的 `modes.rigor` 自测**：30 份前置文档、58 分钟，盲评排最后。多出来的文档买到的是可追溯性，不是更好的游戏。
- **superpowers 7.0.2 的 8/8 提问对照**：从“只问一句选哪个”到“给选项加推荐”，同一场景 8 次全中。提问方式可以被版本化调优。
- **OpenMausBot 的 “Nothing starts by itself”**：每种进入电脑的方式独立开关、默认全关、12 位配对码。安全默认值从“提供开关”变成了“默认不可达”。
- **Scrapling 在喂模型前剥掉 prompt injection**：注入防御放在数据管道里，而不是提示词里。这是本周唯一一个这么做的项目。
- **agent-browser 的“失败要大声”**：点击被遮挡时提前失败并报出遮挡元素，而不是假装成功。**在 agent 工具里，诚实的错误比漂亮的成功更值钱。**

## 结语

这一周的主题不是“agent 更强了”，而是“agent 该归谁管”。第一名是控制台，许可证在改，配置权限在收，提问在被调优，连“出错时说不说实话”都成了 CLI 的卖点。**执行能力已经不是瓶颈，治理才是：谁有权限、谁承担责任、出事时留下什么证据。**

非 AI 的四个位置也不必读成退潮。基础设施回来了，只是换了一种身份——它们不再以“某某框架”出现，而是以“agent 的输入管道、工作区和语料”出现。真正还站在 agent 之外的，只有那个还在改窗口管理器的项目。

榜单是注意力的快照，下周它很可能又换一副面孔。但有一件事大概不会变：**当一个东西能被自动完成，人们就开始关心它能不能被信任、被审计、被拿回去自己改。**
