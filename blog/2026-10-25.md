上周的热榜在争论“Agent 该不该去读没有源码的软件”。本周的答案不再是能不能，而是**读完之后怎么证明自己没读错**。

[Cloudflare 的 security-audit-skill](https://github.com/cloudflare/security-audit-skill) 一周涨了 1.27 万星，把这个问题的工程答案直接开源：六阶段流程、覆盖率账本、每条结论必须有源码证据、**发现者不能自己验证自己的发现**。与此同时，Anthropic 两个官方目录、Cursor 的插件规范、Google 的 Android 技能库在同一周挤上榜单——四家平台不约而同地把“技能从哪装”当成了产品的一部分。

> 说明：本文依据 [GitHub Trending weekly](https://github.com/trending?since=weekly) 于 2026 年 10 月 25 日抓取的公开页面，结合各仓库 README、GitHub REST API 元数据与最近发布记录整理。本次页面解析出 **15 个**热门仓库；“本周新增 stars”与“总 stars”取自抓取时页面可见数据，其余元数据取自 API。Trending 反映短期关注度，不等同于长期采用率；“为什么变热”是结合项目定位、周增量、提交与发布节奏所做的判断，不是平台给出的归因。

## 本周总览

先说结论：

- **本周没有严格意义上的非 AI 项目。** 15 个仓库全部服务于 Agent 工作流或其推理基础设施，这是近几个月第一次出现零非 AI 的一周。不是分类偷懒：`vllm` 是推理引擎，`ComfyUI` 是生成式媒体引擎，其余 13 个直接是 Agent 工具。
- **安全审计第一次被写成了可复用的流程，而不是一段提示词。** Cloudflare 的技能把审计拆成侦察、覆盖式猎捕、候选验证、结构化输出、独立复核、目标中立报告六个阶段，连“什么算确认”都有 JSON Schema 约束。
- **“官方技能目录”成了平台竞争的新战场。** Anthropic 的 `claude-plugins-official` 与 `knowledge-work-plugins`、Cursor 的 `plugins`、Google 的 `android/skills` ——四家在同一周上榜，格式都在向 `SKILL.md` 与 `plugin.json` 收敛。
- **记忆层的技术路线出现共识：不要向量库。** `ai-memory` 用 git 管理的 Markdown wiki，`graphify` 用本地确定性 AST 图，两家都强调“可读、可 diff、可重建、零 LLM 调用”。
- **多 Agent 并行已经是 IDE 级问题。** `orca` 一周涨 9,828 星，靠的不是新模型，而是 worktree、端口、SSH、手机端监控这一整套“养一支 agent 队伍”的琐碎工程。
- **冠军在冷却，榜单在通胀。** 上周冠军 `rea` 的周增从约 24 万骤降到 7.86 万；`CLI-Anything` 自 9 月 22 日之后没有推送，本周仍涨 3,069 星。星数与工程活跃度已经明显脱钩。

## AI 热门项目

### 1. [morluto/rea](https://github.com/morluto/rea)

- **它是做什么的**：面向逆向工程的 MCP 服务器。装上之后，Agent 可以检查原生二进制、Go/Rust 产物、WASM、EVM 字节码、Android APK、固件、pcap 抓包、JavaScript/Electron 应用等；它自己不实现反汇编器，而是把 Hopper、Ghidra、IDA、Kuna、JADX、binwalk、tshark 统一成受控 provider，缺哪个让用户自己装。MIT，TypeScript，2026 年 4 月创建。
- **为什么这周会热**：本周新增约 **7.86 万** stars，总 stars 约 **37.94 万**，仍是全榜周增第一，但已经比上周的约 24 万少了三分之二。更有意思的是 fork 数：9.48 万，约为星数的四分之一。**这种 fork/star 比例通常不是“我要改代码”，而是“先存一份，怕以后没了”。** 一周之内从传播峰值滑向日常，符合社交平台驱动的涨星曲线。
- **有什么新意**：这周的更新反而很“小”——6.7.0 只修了一件事：MCP 客户端的配置文件里如果出现重复的 JSON/JSONC 成员，setup 要改最后一个（客户端真正读取的那个），卸载时如果删除会导致被遮蔽的重复项重新生效，就拒绝执行。为一个配置重复键写专门语义并拒绝危险删除，说明项目已经从“demo 阶段”进入“别把我用户的配置搞坏”阶段。**一个逆向工具开始在意配置文件的边界情况，比它再支持十种文件格式更值得信任。**

### 2. [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)

- **它是做什么的**：把 Cloudflare 内部漏洞挖掘流水线拆出来的开源技能。运行方式极简——在代码库里让 Agent 做一次安全审计，技能自动激活，按六个阶段推进：侦察（产出 `architecture.md` 与 `coverage-ledger.json`）、覆盖率驱动的猎捕（每个账本单位派独立 hunter，再用 critic 找缺口）、候选验证（每个候选项交给一个全新的 verifier 去**证伪**）、结构化输出（`findings.json` 按 `report-schema.json` 校验）、独立记录复核、目标中立的报告生成。MIT，JavaScript，2026 年 6 月创建。
- **为什么这周会热**：本周新增约 **1.27 万** stars，总 stars 约 **4.49 万**，2,785 个 fork。它在 Trending 页面的渲染顺序上排第一，而周增并不是第一——这说明它拿到的是“当下最热”的位置，而不是“本周累计最多”。真正的推力是 Cloudflare 官方博客那篇 *Build your own vulnerability harness*：文章讲的是一套已经跑在 Cloudflare 全网的流水线，这个仓库是它收敛成的单仓起点。**大厂把内部安全流水线开源，比自己写一篇安全白皮书有说服力得多。**
- **有什么新意**：三个设计约束值得抄。第一，**结论只有三态**：`confirmed` 必须有完整源码链路和有界观测结果，`needs_validation` 必须写清那个没查实的具体事实且不许带严重性，`rejected` 要记录被证伪的理由——没有“疑似高危”这种糊弄项。第二，**举证分离**：验证者永远不是发现者，替换结论要再过一次独立验证。第三，**没有沙箱就不执行**：它要求一个禁止外网、环境变量白名单、有资源上限、只允许写指定目录的 OS 级沙箱；没有这套控制，就一律降级为 `needs_validation`，宁可少报。附带两个零依赖的 `.cjs` 校验器（覆盖率账本与结论文件各一个），把“审计做完了没有”变成可以跑 `node` 检查的文件。**安全工具最难的不是找到问题，而是让“没找到”也变得可信——覆盖率账本就是干这个的。**

### 3. [stablyai/orca](https://github.com/stablyai/orca)

- **它是做什么的**：一个“Agent 舰队”工作台，桌面端 macOS/Windows/Linux 加 iOS/Android 伴侣应用。核心是给每个编码 agent 分配独立 worktree，在同一个界面里并排跑 Codex、Claude Code、OpenCode、Pi 等，配 WebGL 终端、无限分屏、可持久化滚动缓冲、SSH 远程 worktree、GitHub/Linear 原生面板、diff 行内批注直接回给 agent。支持 30 多个 CLI agent（README 里连 Hermes Agent 也列了），也能用 `orca worktree create / snapshot / click / fill` 让 agent 反过来驱动 Orca。MIT，TypeScript，2026 年 3 月创建。
- **为什么这周会热**：本周新增约 **9,828** stars，总 stars 约 **10.5 万**，6,633 个 fork。它涨的不是概念，是**日常使用的痒点**：同时开三四个 agent 之后，端口冲突、分支互相踩、找不到哪个窗口在跑什么，这些琐事会立刻压过模型能力带来的快感。项目几乎每天发版（本周当天仍在发 v1.4.240），changelog 才是真正的功能列表。
- **有什么新意**：两个设计细节比功能清单更能说明方向。一是 **Design Mode**：在真实 Chromium 窗口里点任意 UI 元素，把它的 HTML、CSS 和裁剪好的截图直接塞进 agent 的 prompt——绕开了“文字描述界面”这个一直很别扭的环节。二是 **账户与用量面板**：能看到 Claude 与 Codex 的用量和限流重置时间，并热切换账号。当工具开始管理“订阅额度”，说明它已经承认用户的真实约束不是模型不够聪明，而是配额不够用。需要提醒的是 **8,611 个未关闭 issue**——这种量级既证明采用面广，也说明维护压力已经相当大。

### 4. [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)

- **它是做什么的**：把一个代码库连同文档、SQL schema、配置和 PDF 一起变成可查询的知识图谱。用 tree-sitter 做本地确定性 AST 解析（覆盖约 40 种语言的 calls/imports/inherits/mixes_in），用 Leiden 算法切社区，给每个节点算“枢纽度”，输出三个文件：`graph.html`（可点可搜）、`GRAPH_REPORT.md`（要点与可疑连接）、`graph.json`（完整图）。之后用 `graphify query / path / explain` 在图上提问，而不是让模型重新读一遍仓库。Apache-2.0，Python，2026 年 4 月创建。
- **为什么这周会热**：本周新增约 **6,868** stars，总 stars 约 **13.45 万**，12,839 个 fork，1,619 个未关闭 issue。它踩中的是“大仓库里 agent 读不完”这个刚性成本，而它的卖点是**建图零 LLM 调用**：AST 解析全在本地，只有对文档/媒体的语义补充才可选调用后端。
- **有什么新意**：**每条边都带置信标签**——`EXTRACTED` 表示源码里明确写了，`INFERRED` 表示是解析推导出来的。这一条比图谱本身重要：它让“模型以为的调用关系”和“代码里真有的调用关系”不会混在一起。README 还给了一组少见的具体数字：LOCOMO（n=300）recall@10 为 0.497，对比 mem0 的 0.048、supermemory 的 0.149；LongMemEval-S 的 QA 准确率 76%，与稠密 RAG 持平；ERPNext 跨工具关键事实覆盖率 82.0%，高于 grep/read 基线的 70.8%。这些数字由同一套 harness、同一模型、预算相同跑出，评审模型做了双盲一致性校验（一致率 90.6%，kappa 0.81）。**在一个习惯用“感觉更准”宣传的品类里，给出可复现的对照表和 κ 值，本身就是差异化。** 需要说明：图谱云端版是商业产品，README 里的 80% token 节省属于厂商自述。

### 5. [anomalyco/opencode](https://github.com/anomalyco/opencode)

- **它是做什么的**：开源的编码 Agent，终端优先，MIT，TypeScript，2025 年 4 月创建。这一条几乎不需要解释——它是过去一年里“开源 Claude Code 替代品”这条赛道最稳定的选手之一。
- **为什么这周会热**：本周新增约 **6,857** stars，总 stars 约 **22.11 万**，2.96 万 fork。**这次没有版本事件，也没有新功能发布可讲**——它已经进入“基础设施式增长”：MCP 生态、第三方 GUI 与 harness 把它当默认后端，每个新工具都在给它的 README 贡献一次曝光。
- **有什么新意**：本周的价值不在项目，而在它代表的位置。当 `orca`、`ai-memory`、`ruflo` 这些项目在 README 里把 OpenCode 与其他 CLI agent 并列支持时，OpenCode 就从“一个工具”变成了“一个必须兼容的接口”。**开源项目最难得的状态不是被讨论，而是被当作依赖。**

### 6. [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)

- **它是做什么的**：把 HTML、CSS、媒体和可 seek 的动画渲染成确定性 MP4 的框架。可以当本地 CLI，可以作为技能给 coding agent 用（`/hyperframes` 是路由器），也可以是托管创作产品的渲染内核。Apache-2.0，TypeScript，要求 Node 22 以上，2026 年 3 月创建。
- **为什么这周会热**：本周新增约 **5,633** stars，总 stars 约 **7.16 万**。这是它**连续第三周在榜**：两周前约 4,081，上周约 5,639，本周 5,633 ——增速高位横盘。这种曲线比一次性爆发更有意思：说明有一批人在持续使用，而不是只在转发 demo。
- **有什么新意**：它坚持 HTML 作为中间表示——可读、可 diff、可 lint、可 seek、可预览，最后一次性渲染。这个选择和上周的 ArtCraft（图层 + 3D 场景）形成对照：**一个用文档结构约束生成，一个用场景结构约束生成，共同点是都不相信“一句话生成一段视频”。** 对工程团队来说，HTML 这条路的额外好处是渲染结果可进 CI：同样的输入必须出同样的帧。

### 7. [Comfy-Org/ComfyUI](https://github.com/Comfy-Org/ComfyUI)

- **它是做什么的**：节点式扩散模型 GUI 与后端，本地推理引擎，GPL-3.0，2023 年 1 月创建。生成式媒体领域事实上的公共工作台。
- **为什么这周会热**：本周新增约 **4,648** stars，总 stars 约 **14.27 万**。这不是新项目翻红，而是长期基础设施的又一次波动：本周发布 v0.42.1（10 月 19 日），修的是部分用户跑 MOSS 图像模板工作流时的崩溃问题——**一条只有一句话的更新说明，恰恰说明它的用户基数大到“个别用户崩溃”也值得单独发版**。
- **有什么新意**：本周没有架构层面的新东西。它上榜的意义在于提醒：当整个榜单都在讨论 agent 的流程与治理时，真正被用来产出图像/视频的仍然是这种“节点图 + 本地推理”的老形态。**创作工具和 agent 工具正在分叉：前者追求可控的确定性，后者追求自主的编排。**

### 8. [akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory)

- **它是做什么的**：给编码 Agent 用的长期记忆服务，Rust 编写，MIT，2026 年 5 月创建。目标场景写得很具体：在 Claude Code 里干到一半退出，在同一个目录打开 Codex，接着干——不用重新解释架构、失败的尝试和还悬着的问题。支持二十多个 harness，记忆存在你自己跑的服务器上，多机可用，团队可以共用一个服务端。
- **为什么这周会热**：本周新增约 **3,541** stars，总 stars 约 **1.33 万**，却只有 **29 个未关闭 issue**。这个组合很少见：涨得不慢，但 issue 区极干净。说明它要么用户面还窄，要么质量确实稳。
- **有什么新意**：三个决定值得单独说。第一，**记忆本体是 git 管理的普通 Markdown wiki**，数据库只是可重建的派生索引——能 `grep`、能丢进 Obsidian、能手改、能 `rsync`，“没有向量库要维护，内容也不锁在二进制块里”。第二，**代理之间的交接是类型化协议**：每个 handoff 有 owner、可被 claim，跨 harness 时远端只收到 harness 与会话标识，不传本地 transcript 路径和正文。第三，**记忆老化不调用模型**：按可调的时间曲线衰减，被打开、被搜索、被链接引用过的记忆衰减更慢，冷掉的片段压缩成硬事实（文件路径、错误码、决策）而不是直接丢弃，近重复合并、疑似矛盾标红，全部零 API 调用。**“记忆治理”第一次被做成了不依赖 LLM 的确定性机制——这比再叠一层摘要提示词可靠得多。**

### 9. [ruvnet/ruflo](https://github.com/ruvnet/ruflo)

- **它是做什么的**：自称“Agent 元 harness”，包在 Claude Code 与 Codex 外面，提供 100 多个专用 agent、swarm 编排、自学习记忆、跨机器联邦通信和一套企业护栏。一次 `npx ruflo init` 之后按原来的方式用 Claude Code，hooks 在后台做任务路由与协调。MIT，TypeScript，前身是 2025 年 6 月的 Claude Flow。
- **为什么这周会热**：本周新增约 **3,241** stars，总 stars 约 **7.91 万**。它是榜单上的老面孔，本周没有结构性版本事件，属于典型的口碑长尾。
- **有什么新意**：这周最值得记的不是功能，而是**README 里的自我限定**。项目明确写道：这段血缘说明“Ruflo 的来历，而不是在所有 Claude Code 工具里的首创”。在一个靠“the original agent harness”当标题的品类里，主动给自家叙事加限定条件，反而让其余声明更可信。工程侧的卖点依然是规模：314 个 MCP 工具、26 条 CLI 命令，用户不需要学它们，init 之后由 hooks 接管。**规模本身就是一种设计选择，问题只在于用户能不能在不理解 314 个工具的情况下安全地使用它。**

### 10. [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official)

- **它是做什么的**：Anthropic 官方维护的 Claude Code 插件目录，分 `/plugins`（自研）与 `/external_plugins`（合作方与社区），用 `/plugin install {name}@claude-plugins-official` 安装。Apache-2.0，2025 年 11 月创建。
- **为什么这周会热**：本周新增约 **3,232** stars，总 stars 约 **4.44 万**，1,211 个未关闭 issue。**issue 数量是这类目录型仓库的真实指标**：它同时是市场、规范和工单入口，三者共用一套编号。
- **有什么新意**：规则写得像包管理器而不是营销页：`name` 是不可变 slug，改标签只能动 `displayName`，真要改名必须写进顶层 `renames` 让老用户自动迁移；没有 `plugin.json` 的技能仓库可以用 `strict: false` 加显式 `skills` 数组挂进来。README 顶部还有一段罕见的安全声明：Anthropic 不控制插件里的 MCP 服务器与文件，也无法验证它们以后不会变。**插件生态走到第二年，补的正是“命名空间”和“信任边界”这两门必修课。**

### 11. [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything)

- **它是做什么的**：把各种现有软件包成 CLI，让 Agent 能操作它们——从 Obsidian、Joplin、Calibre、LibreOffice、Zoom 到 Rekordbox、3MF、ArcGIS Pro，配一个公开注册表 CLI-Hub（`clianything.cc`），还接受“希望支持某软件”的 wishlist 请求。Apache-2.0，Python，2026 年 3 月创建。
- **为什么这周会热**：本周新增约 **3,069** stars，总 stars 约 **5.69 万**，但**仓库最后一次 push 是 9 月 22 日**，README 里的 News 也停更在 5 月。这是本周最值得注意的一组矛盾数据：**一个多月没有提交的项目仍有三千周增**。它说明这类“给 Agent 补软件接口”的仓库正在被反复发现和引用，而项目本身的推进节奏已经落后于传播节奏。
- **有什么新意**：它的核心判断写在海报上——*Today's Software Serves Humans. Tomorrow's Users will be Agents.* 实现路径不性感但有效：不改造软件，只包一层稳定的 CLI 契约，让 agent 通过命令行完成真实工作流，并且要求每个 CLI 带测试（README 里能看到“134 个测试基线”“41 个单元测试 + 真实 Calibre E2E”这类记录）。安全事件也出现在自己的 changelog 里：Sketch CLI 的 token 文件处理被加固以防路径穿越与符号链接逃逸，XML/SVG/ODF 解析统一走 `defusedxml`。**当一个“给 agent 装手”的项目开始系统性处理不可信输入，它才真正进入了生产环境。**

### 12. [anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins)

- **它是做什么的**：面向知识工作者的开源插件集，为 Claude Cowork 打造，同时兼容 Claude Code。一次放出 11 个按职能划分的插件——生产力、销售、客户支持等，每个打包了技能、连接器、斜杠命令和子 agent。连接器覆盖面很广：Slack、Notion、Asana、Linear、Jira、Monday、ClickUp、HubSpot、Microsoft 365 等。Apache-2.0，2026 年 1 月创建。
- **为什么这周会热**：本周新增约 **2,631** stars，总 stars 约 **3.27 万**。它与 `claude-plugins-official` 同周在榜，构成了 Anthropic 的两条分发线：一条是**目录**（让别人把插件交上来），一条是**样板**（自己做一套给非工程岗用）。
- **有什么新意**：它把“角色”当成插件的组织单位，而不是按能力切分。销售插件里预先写好了线索调研、通话准备、管道复盘、竞品战卡的流程；支持插件里写的是工单分流与回复打包。对企业的实际含义是：**买回来的不是一个通用助手，而是一套“你这个岗位该怎么做”的默认约定**，改的是术语、工具和流程，而不是模型。这和上一代“给每个部门发一个 ChatGPT 账号”是两种完全不同的落地方式。

### 13. [cursor/plugins](https://github.com/cursor/plugins)

- **它是做什么的**：Cursor 的插件规范与官方插件集合。每个插件是仓库根目录下的独立目录，自带 `.cursor-plugin/plugin.json` 清单。已收录的插件包括 `thermos`（带并行子 agent 的分支安全与正确性审查）、`ralph-loop`（自指迭代循环）、`continual-learning`（用高信号要点增量更新 `AGENTS.md` 的记忆方案）、`agent-compatibility`（对照真实环境审计启动、校验与文档）等。TypeScript，2026 年 1 月创建。
- **为什么这周会热**：本周新增约 **1,729** stars，总 stars 约 **1.39 万**，371 个未关闭 issue。绝对量不大，但它是“IDE 厂商开始定义插件规范”的明确信号。
- **有什么新意**：**这个仓库没有 LICENSE 文件**——对一个以“规范”为核心的仓库来说，这是需要留意的空白：代码可用性与规范复用条件都没写清楚。另外一个值得抄的做法是 `continual-learning` 的思路：不维护长篇记忆，只用高信号要点增量更新 `AGENTS.md`。**比起“让模型记住一切”，把约定写进仓库里可评审的文本，才是团队真正需要的记忆形式。**

### 14. [vllm-project/vllm](https://github.com/vllm-project/vllm)

- **它是做什么的**：高吞吐、显存高效的 LLM 推理与服务引擎，Apache-2.0，2023 年 2 月创建，来自 UC Berkeley Sky Computing Lab，现在由 2000 多名贡献者共同维护。
- **为什么这周会热**：本周新增约 **1,371** stars，总 stars 约 **9.54 万**。驱动力是 10 月 18 日发布的 **v0.32.0**：814 个提交、363 位贡献者（其中 121 位是新贡献者）。这是典型的“版本事件型”上榜，不是叙事型。
- **有什么新意**：这个版本最有信息量的其实是**删掉了什么**。破坏性变更清单包括：停止支持 Python 3.10、默认 CORS 不再放行所有来源、移除 torch.compile 的序列并行与 AsyncTP 传递、移除 cascade attention、移除 `mamba_cache_mode="all"`、`max_tokens` 不再从上下文窗口里预留。同时把低精度 KV cache 铺到全线：NVFP4 KV cache 扩到 SM8x/SM12x/SM90，GLM-5.x 在 SM100 上默认 FP8 KV cache（每 rank 的 KV 显存减半，吞吐 +2.3–5.5%，TTFT 代价 7–11%），ROCm 有了 4bit `ultraquant_4bit`（密度约为 FP8 的两倍）。另有三条 GHSA 安全修复、多模态共享内存句柄签名、超过 64 层的 JSON Schema 被拒绝。**一个成熟基础设施项目的健康标志，是它敢于持续删除历史包袱，而不是不断加开关。**

### 15. [android/skills](https://github.com/android/skills)

- **它是做什么的**：Google 官方的 Android 技能库，给 Agent 提供“AI 优化过的模块化指令”，遵循开放标准的 agent skills 格式（`SKILL.md`）。用 Android CLI 安装：`android skills add r8-analyzer --project=.`，`--all` 装全套；没指定 agent 时默认装到 `~/.gemini/antigravity/skills`。Apache-2.0，Kotlin 为主的示例代码，2026 年 3 月创建。
- **为什么这周会热**：本周新增约 **1,317** stars，总 stars 约 **9,612**，只有 34 个未关闭 issue。周增是全榜最低，但它的意义不在数量。
- **有什么新意**：README 里那句取舍写得很清楚——**只做“评估显示 LLM 表现不佳”的场景**，不重复 Jetpack Compose 这类模型已经很熟练的领域。这是官方技能库第一次公开承认自己的边界，也给出了技能该写什么的判断标准：**不是把文档抄一遍，而是补模型的能力缺口。** 与 Anthropic、Cursor 的目录放在一起看，格式之争基本结束，接下来比的是“谁的技能真的改变了模型的行为”。

## 非 AI / 泛基础设施

**本周严格与 AI 无关的项目是 0 个。** 15 个仓库里，13 个直接是 Agent 工具链，2 个是推理与生成基础设施（`vllm`、`ComfyUI`）——后者服务的是模型本身，也不能算非 AI。

#### 为什么这周一个都没有

上周还有两个贴着二进制的项目（AnyPS5、Ghidra），本周连这种边缘位置都没有了。原因是三层叠加：一是**平台方亲自下场**，Anthropic、Cursor、Google 在同一周发布官方目录，占掉四个位置；二是**基础设施项目进入了版本空窗**（本周只有 vLLM 有实质版本事件）；三是**榜单本身的容量只有 15 个**，而 Agent 工具正在以每周一批的速度产出新仓库。

这不代表非 AI 项目不值得看，只代表它们这一周没有拿到注意力。对读者更实用的做法是：把这份榜单当“Agent 工具链的供给清单”，把 `vllm`、`ComfyUI` 这两条当成“模型侧的稳定基线”，其余项目三个月后再回来看还有几个在更新。

## 技术趋势分析

**一、Agent 的交付物从“结果”变成“证据”。** Cloudflare 的技能把审计拆成六个阶段，核心不是让模型更能找漏洞，而是让**结论可被机器复核**：覆盖率账本说明查过哪些面，三态结论区分“确认”“待验证”“已排除”，发现者与验证者强制分离，最后用 schema 校验文件。这套结构可以平移到合规、迁移评估、依赖审计。**接下来一年，Agent 工具的分水岭会是“能不能证明自己没漏”，而不是“能不能做得更快”。**

**二、技能与插件已经变成发行渠道，而不是提示词合集。** 本周四个官方目录同台：Anthropic 两条线（目录 + 岗位样板）、Cursor 的规范、Google 的 Android 技能。它们的共同动作是定义清单文件（`plugin.json`）、命名规则、不可变标识与迁移机制。**当一个生态开始写“改名要走 `renames`”，它就从“好玩”进入了“要负责”的阶段。**

**三、记忆层的共识是“可读、可重建”，而不是“更大更聪明”。** `ai-memory` 用 git + Markdown 当真相源、数据库只是可重建索引，衰减、去重、矛盾标记全部零 LLM 调用；`graphify` 用本地 tree-sitter AST、Leiden 社区、零 LLM 建图。两家路线不同（一个是对话记忆，一个是代码知识），但都拒绝向量库当唯一真相。**原因很实际：向量库不可 diff、不可评审、重建成本高——而团队真正需要的是能进 PR 的记忆。**

**四、多 Agent 并行的问题已经下沉到工程细节。** `orca` 涨 9,828 星靠的是 worktree 隔离、端口探测、SSH 远程执行、手机端监控、用量与账号切换。这些都不是模型能力问题，而是“同时养四支队伍”的组织问题。它的 8,611 个未关闭 issue 也提示了代价：**一旦工具接管了用户的工作台，维护成本会随功能面积线性上升。**

**五、成熟基础设施靠删除维持速度。** vLLM 0.32 一口气移除 Python 3.10、cascade attention、AsyncTP 传递和若干兼容开关，同时收紧默认 CORS、给多模态共享内存句柄签名。对比之下，Agent 工具这一侧还在做加法（314 个 MCP 工具、30 多个支持的 agent）。**两条曲线迟早会相交：Agent 工具也会走到必须删除的那一天。**

**六、星数继续通胀，需要用第二指标校正。** 本周最典型的三组数字：`rea` 周增从 24 万降到 7.86 万但 fork 高达 9.48 万；`CLI-Anything` 一个月没提交仍涨 3,069；`ai-memory` 只有 29 个未关闭 issue。**判断一个项目，周增看注意力，issue/提交比看维护强度，fork/star 比看“恐慌性备份”的程度。**

## 本周最值得关注的新鲜点

- **Cloudflare 的三态结论**：`confirmed` / `needs_validation` / `rejected`，且 `needs_validation` 不许带严重性。把“没查实”做成一等公民，是安全类 Agent 输出最缺的一课。
- **`ai-memory` 的零 LLM 记忆治理**：衰减按时间曲线、访问加权延长、冷片段压成硬事实、近重复合并、矛盾标记，全部不调模型。记忆系统终于开始算“存储成本”而不是只算“召回率”。
- **`graphify` 的边置信标签**：`EXTRACTED` 与 `INFERRED` 分开标注，让“代码里真有的关系”和“推导出来的关系”不会混为一谈。这个约定应该成为所有代码图谱的默认字段。
- **`orca` 的 Design Mode**：点一下界面元素，HTML、CSS 和截图直接进 prompt。绕开“用文字描述 UI”这个长期低效环节，比任何“多模态理解”宣传都实在。
- **vLLM 的删除清单**：Python 3.10 退场、cascade attention 移除、CORS 默认收紧。一个项目敢在 814 个提交的版本里做这些减法，说明它的用户已经过了“什么都要兼容”的阶段。
- **四家平台的官方目录同周在榜**：Anthropic ×2、Cursor、Google。技能分发从社区自发进入平台编制，`SKILL.md` 事实上成了跨平台的最小公约数。

## 结语

这一周最清楚的信号不是某个项目涨了多少星，而是**榜单上几乎每个项目都在回答同一个问题：Agent 干完活之后，凭什么让人相信它干对了？**

Cloudflare 的答案是流程与账本，`graphify` 的答案是给每条边标上置信度，`ai-memory` 的答案是把记忆写成可评审的 Markdown，vLLM 的答案是删掉不确定的路径、把默认值收紧。四种答案，同一个方向：**从“看起来很能干”转向“可以复核”。**

至于零非 AI 项目这件事，不必过度解读成“开源只剩 AI”。更准确的读法是：这一周供给端的所有注意力都被 Agent 工具链吸走了，而基础设施项目正好处在版本空窗。榜单是注意力的快照，不是技术的地形图——下周它很可能又换一副面孔。
