上周的榜单在问：谁来验收 agent 的产出？

本周的答案变得具体了——**给 agent 一副能自检的手，再给它一张能被机器核对的成绩单。**

[Univer](https://github.com/dream-num/univer) 一周涨 **7,240** 星，是全榜唯一超过七千的项目。它原来的定位是开源电子表格，这周 README 的第一句话变成了“用 Univer Office SDK 搭你自己的 AI 办公室”：agent 通过 Headless API 改内容、渲染截图自查、在隔离的 Worktree 里改草稿，最后由人合并。另一边，阿里把内部用了两年的 AI 代码评审工具 [open-code-review](https://github.com/alibaba/open-code-review) 开源，核心主张只有一句：**确定性的部分交给工程，动态决策交给模型**，于是同等模型下 token 只用通用 agent 的九分之一。再往下，[ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) 给 agent 配了 42 个 FFmpeg 工具，每个都带机器可读的输入契约，还写了一组“每个工具都必须过”的守卫测试。

三个项目、三种介质（文档、代码、视频），同一个动作：**把“做完了”变成“验过了”。**

> 说明：本文依据 [GitHub Trending weekly](https://github.com/trending?since=weekly) 于 2026 年 11 月 22 日 12:00 左右抓取的公开页面，结合各仓库 README、GitHub REST API 元数据与最新 release 记录整理。本次页面解析出 **13 个**热门仓库，合计周增 **45,527** 星，平均每个 3,502 星。需要说明四点：同一时刻抓取 Trending 返回的组合与排序会变化，本文只对这一次快照负责；**页面顺序不是按周增 stars 排序的**（Univer 在页面上排第 12，却是本周增星第一），下文 AI 分组内按周增重排；总 stars / fork / 未关闭 issue / 创建时间 / 许可证取自 API 抓取时刻（未关闭 issue 数包含 PR）；“为什么变热”是结合项目定位、发版节奏与提交记录做的判断，不是平台给出的归因。

## 本周总览

先说结论：

- **没有爆款，但总量并不低。** 13 个仓库合计 45,527 星，比上周 11 个仓库的 61,501 星少 26%。差别几乎全在上周那个异常值：astryx 一家 13,660 星。剔除它之后，两周的“中位数项目”其实差不多（本周 3,502 星/仓库，上周 5,591 星/仓库仍更高，因为榜单变长了）。
- **第一名是办公套件，卖点是“agent 能自己验”。** Univer 7,240 星，占全榜 15.9%，总 stars 31,115。它这周把定位从“开源表格”改成“Office SDK”，并在 11 月 21 日发了 v1.6.0。真正值得记的不是甘特图和移动端 PDF，而是 README 里那套 agent 工作流：改内容 → 渲染截图 → 版式 lint → 在 Worktree 里等人审。
- **“确定性工程 + agent”第一次被写成可量化的卖点。** open-code-review 给出了 benchmark：50 个开源仓库、200 个真实 PR、10 种语言、80+ 位资深工程师标注的 1,505 个问题；同等模型下 Precision 与 F1 高于通用 agent，token 约为 **1/9**，代价是 Recall 更低——这是刻意选择，宁可少报，不要噪音。
- **技能继续当分发渠道用。** stitch-skills 走 Codex/Claude/Cursor 的插件市场，modern-web-guidance 用 `npx modern-web-guidance install` 装进 50+ 个 agent 宿主，ffmpeg-skill 一个 `npx` 加一个 MCP server，astryx 的 CLI 现在每个命令都暴露成 MCP 工具。**安装方式正在收敛成“一条 npx + 一个 MCP 端点”。**
- **协议层这周真的冻结了。** AG-UI 1.0 规范定稿，TypeScript / Python / .NET SDK 从 JSON Schema 生成，0.x 与 1.0 双向兼容。它和 MCP（工具）、A2A（agent 之间）拼成三层。601 个未关闭 issue 说明这不是没人用的“标准”。
- **严格非 AI 只剩两个。** sure（个人财务，Ruby）和 HermesEnabler（Apple Watch 表盘，Objective-C）合计 2,565 星，占 5.6%。剩下 11 个位置、94.4% 的周增都在 AI 侧，其中 4 个直接做“验证/评审”。这个比例比上周更极端。

## AI 热门项目

### 1. [dream-num/univer](https://github.com/dream-num/univer)

- **它是做什么的**：一套把 Office 能力嵌进自有产品的 SDK。**Web SDK** 是底座：内容模型与快照格式、插件与依赖管理、命令系统、公式与渲染引擎、Facade API，以及 Sheets / Docs 的编辑能力；**Server SDK** 补实时协作、编辑历史、Office 文件导入导出；**AI SDK** 把内容操作、执行、视觉检查接到现有 agent 上。开源的是 Web SDK 核心，Apache-2.0；Server SDK 与商业插件单独授权。2022 年 9 月创建，TypeScript。
- **为什么这周会热**：本周新增约 **7,240** stars，总 stars 约 **3.11 万**，2,837 个 fork（9.1%），204 个未关闭 issue，**v1.6.0 于 11 月 21 日发布**，当天还有 UI 修复提交。周增是全榜第一，也是唯一一个把“AI office”写进仓库描述的办公类项目。一个做了四年的国产开源表格项目，靠重新定位拿到今年最高的一次曝光，这件事本身就值得记。
- **有什么新意**：v1.6.0 的功能清单很长——Base 甘特图加了计划排期与前置依赖（拖拽建 finish-to-start 链接、拒绝成环、协作可撤销）、移动端支持 PDF 查看与编辑、PDF/Data 功能区重排、新增 `AMORDEGRC` 与 `EUROCONVERT` 两个财务函数、客户端与协作服务同时收紧编辑/评论权限。但真正的新意在架构叙事：**同一份 Unit 快照（`IWorkbookData` / `IDocumentData` / `ISlideData`）同时服务浏览器编辑器、后端服务和 agent。** agent 走 Headless 模式改内容，用浏览器 Render Runtime 截图核对，Slide 版式 lint 会给出“文字出界/重叠”这类结构化结论，改完的草稿放在隔离 Worktree 里，等人 review / merge / reopen。**它把“agent 改文档”拆成了编辑、自检、交付三段，每一段都有可回滚的边界。**

### 2. [GoogleChrome/modern-web-guidance-src](https://github.com/GoogleChrome/modern-web-guidance-src)

- **它是做什么的**：Modern Web Guidance 的**源仓库**（可分发包是 `GoogleChrome/modern-web-guidance`）。做的事很聚焦：把“现代 Web 平台该怎么写”变成技能，塞进 coding agent 的上下文，阻止模型继续输出 jQuery 时代的写法。覆盖 **262 个现代 Web 特性、204 个真实开发场景**，分 CSS 布局、UX、性能、表单与 UI、无障碍、内置 AI 六类。CLI 支持 `install` / `search` / `retrieve` / `legacy-scan`，Node 22+。由 Chrome、Edge、Firefox、MDN 四个团队共同维护。
- **为什么这周会热**：本周新增约 **4,400** stars，总 stars 约 **9,935**，796 个 fork，384 个未关闭 issue。**一周拿走了它生命周期 44.3% 的星**——这是本周“注意力最集中”的一个数字，比排名更有信息量。仓库没有 GitHub Release（版本走 npm），最近的提交集中在 CLI 的工程细节：`legacy-scan --max-files` 与部分覆盖报告、按包管理器自动挑 skills runner（pnpx / yarn dlx / npx -y）。
- **有什么新意**：它的方法论比内容更值得抄：指南是**按 token 效率设计的**，用 eval 把“模型本来就会”的最低共同分母剪掉，只留下模型容易用错、或者根本不知道的现代 API。这解释了一个反直觉现象——一个“文档仓库”能拿 4,400 星，因为大家真正缺的不是更多文档，是**能塞进上下文窗口的那 3KB**。另外 `legacy-scan` 把技能从“生成时提示”扩展成“存量代码审计”，这一步让它从提示词工程变成了工程工具。**当模型默认写老代码时，纠正它的知识本身就是基础设施。**

### 3. [mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill)

- **它是做什么的**：一个“按人搜索”的 agent 技能。并行查 Reddit、X、YouTube、TikTok、Instagram、HN、Polymarket、GitHub、arXiv、Techmeme、LinkedIn、Bluesky 等二三十个来源，按真实互动（点赞、upvote、赔率、真金白银）排序，再由 agent 评审合成为一份简报。定位一句话：**Google 聚合编辑，它搜索人。** 安装是 `npx skills add` 或 Claude Code 插件市场，零配置起步，Reddit / HN / Polymarket / GitHub 不需要 key。
- **为什么这周会热**：本周新增约 **4,198** stars，总 stars 约 **7.21 万**，6,386 个 fork（8.9%），**只有 18 个未关闭 issue**——每千星 0.25 个，是全榜最低，和 sure 的 62.8 形成 250 倍的反差。**v4.5.0 于 11 月 21 日发布**。README 里挂着“GitHub Trending #1 Repository Of The Day”的徽章（项目自述，非本文核实）。
- **有什么新意**：v4.5.0 的更新几乎没有“新来源”，全是**来源正确性**：修 Reddit 评论附件的三元组解包、planner 现在尊重“故意省略某个来源”的宿主计划、给 LinkedIn 补上能力声明、故事聚类在标题与角度匹配间共享配额、Exa 搜人时不再拿公司同行顶替、恢复完整的浏览器 cookie 集合、Techmeme 的限流要显式暴露。**一个聚合器成熟与否，看的是它怎么处理“查不到”和“查错了”，而不是能列多少个 logo。** 18 个未关闭 issue 也说明维护者把工单当工单清，不养社区。

### 4. [alibaba/open-code-review](https://github.com/alibaba/open-code-review)

- **它是做什么的**：阿里内部的 AI 代码评审助手，做了两年、服务数万开发者后开源。CLI 读 Git diff，把改动文件交给可配置的 LLM agent，agent 能读整文件、搜代码库、看其它改动文件，产出带行号的结构化评论；`ocr scan` 可以对整个文件或无 diff 的目录做审计。内置多语言规则集（空指针、线程安全、XSS、SQL 注入），OpenAI / Anthropic 兼容端点，Go 编写，Apache-2.0。
- **为什么这周会热**：本周新增约 **4,032** stars，总 stars 约 **5.51 万**，4,573 个 fork（8.3%），341 个未关闭 issue，**v1.14.0 于 11 月 21 日发布**。创建才六个月就有 5.5 万星，靠的是“阿里内部大规模验证过”这句背书——在企业采购语境里，这比任何 benchmark 都好用。
- **有什么新意**：它整篇 README 都在打一个靶子：通用 agent 做评审会**漏文件、漂位置、质量随 prompt 抖动**。对策是把评审拆成两半：文件选择、文件捆绑（`message_en.properties` 和 `message_zh.properties` 捆成一个单元）、规则匹配、评论定位与反思，全部用确定性工程做硬约束；模型只负责动态决策和上下文检索。benchmark 结论也很诚实：**Precision 和 F1 更高、token 约 1/9、速度更快，但 Recall 低于通用 agent，这是刻意取舍。** v1.14.0 的新东西是行为与影响分析、按严重度排序、SQL / Dhall / Ruby 规则、CUDA/HIP 支持。**“宁可少报，不要噪音”是一个产品判断，不是技术缺陷——评审工具最贵的成本从来是误报带来的人工分诊。**

### 5. [meta/astryx](https://github.com/meta/astryx)

- **它是做什么的**：Meta 内部用了八年、支撑 13,000+ 应用的设计系统，今年以 MIT 开源。150+ 无障碍组件、品牌级主题、暗色模式、模板和 CLI；React 19 + StyleX 编写，但消费方不需要采用 StyleX，可以用 Tailwind、CSS Modules 或纯 CSS 覆盖。主题就是一组 CSS 自定义属性，`swizzle` 能把组件源码整份弹出到自己项目里。核心理念是“人和 AI 用同一套参考来搭”。
- **为什么这周会热**：本周新增约 **3,967** stars，总 stars 约 **3.19 万**，2,502 个 fork（7.9%），**937 个未关闭 issue**（每千星 29.4，全榜第二高），**v0.7.17 于 11 月 20 日发布**。它上周是全榜第一（13,660 星），两周合计约 **1.76 万**星。**这是本周最重要的“连续性”证据：一个开源两周的设计系统，第二周仍能拿近四千星，说明它不是一次发布会带来的脉冲。**
- **有什么新意**：v0.7.17 的条目很“移动端”：Item / ListItem 的滑动操作现在会跟手走完 open → confirm → fire → cancel 全流程；TextInput / TextArea / NumberInput 在手机键盘弹出时保持可见、关闭后恢复滚动位置；TopNavMenu 触摸或键盘选择后只关一次并把焦点还给触发元素；Selector 选完回焦，长列表滚动时选中行与触发器对齐。最值得记的是 CLI 侧的改动：**每个命令都暴露成 MCP 工具**，加了一套 one-base 路由，并把可选菜单/提示的初始包体做小。一个设计系统开始按“MCP 客户端能调”来设计 CLI，比它多 20 个组件更能说明方向。

### 6. [ag-ui-protocol/ag-ui](https://github.com/ag-ui-protocol/ag-ui)

- **它是做什么的**：Agent-User Interaction Protocol，把 agent 接到前端应用的开源事件协议。agent 不是请求/响应模型：它流式吐 token、中途调工具、更新共享状态、等人确认、派生子 agent，每个框架的实现都不一样。AG-UI 用一条双向事件流统一：agent 发类型化事件，任何客户端都能渲染，同一个 agent 可以同时驱动 Web、移动端、终端、Slack。与 MCP（工具）、A2A（agent 间）并列。MIT。
- **为什么这周会热**：本周新增约 **3,792** stars，总 stars 约 **2.10 万**，2,148 个 fork（10.2%），**601 个未关闭 issue**（每千星 28.6，全榜第三），11 月 21 日发布了 `release/2026-11-21`。**AG-UI 1.0 规范这周正式冻结**：有 JSON Schema 背书，TypeScript / Python / .NET SDK 全部由 schema 生成，0.x 与 1.0 双向兼容，还配了迁移指南。
- **有什么新意**：协议冻结本身就是一个信号——**在此之前，押注 AG-UI 等于押注一个会变的接口。** 冻结之后，SDK 由 schema 生成意味着三种语言的行为不会再各自漂移，这对“前端团队用 TS、后端团队用 Python”的现实组合很关键。最新一批包更新（`@ag-ui/langgraph` 0.0.47）细节也很能说明成熟度：客户端的 `forwardedProps` 现在只经白名单（`streamSubgraphs`、`durability`）进入 `runs.stream`，`config` 不再覆盖 `assistantConfig`，continue 模式只从线程历史里真正跑过的节点恢复，避免 reducer 通道把值翻倍。**这些都不是新功能，是把“能跑”变成“不会悄悄跑错”。**

### 7. [kajisho5/ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill)

- **它是做什么的**：给 coding agent 的本地视频编辑器。42 个工具覆盖剪切、拼接、去静音、按比例/时长适配、字幕与卡拉 OK、叠加与动效、HDR→SDR 与 LUT、音频修复、多机位、响度、交付检查、整片渲染、批量目录；每个工具都是带类型的 CLI，也都能作为 MCP 工具调用（默认只暴露核心 12 个以省上下文，`FFMPEG_SKILL_MCP_FULL=1` 放开全部 42）。纯本地、Python 标准库、不需要 key。MIT。
- **为什么这周会热**：本周新增约 **3,598** stars，总 stars 约 **9,336**，841 个 fork（9.0%），46 个未关闭 issue，**v4.5.3 于 11 月 22 日（抓取当天）发布**。9 月才创建，两个月不到接近万星，“agent + 视频”这个组合长期缺一个靠谱的本地执行层，它填的正是这个洞。
- **有什么新意**：版本号很密，但最新两个版本讲的是同一件事——**让工具自己证明没干错**。4.5.3 修的是“章节时间戳没跟着裁剪后的片段走”：多段拼接后章节点还停在源时间、超出输出末尾；现在所有改变时长的工具都会在结果里写 `chapters_not_retimed` 警告。更重要的是新增的守卫测试：拿一段 16:9、5.1 声道、带章节和字幕的片子，把**所有工具（含多输入工具）**跑一遍，只要出现“章节时间没重算”“声道丢了/画面被裁没说”“dry-run 报了测量值”“结果首行不是 `wrote`”“工具卡在未关闭的 stdin”就失败。还有一个叫 SPEC 的设计：每个工具的 `input_schema` 不在代码旁边手写，而是运行时从同一个 `argparse` 定义派生，CI 发现漂移就挂。**这是把“文档与实现一致”从人的纪律变成构建约束。**

### 8. [backnotprop/plannotator](https://github.com/backnotprop/plannotator)

- **它是做什么的**：本地、浏览器里的 agent 评审界面。agent 提出计划、规格、HTML 产物或干完活时，页面自动打开，你标注、评论、一键把反馈送回 agent。支持 Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、DeepSeek Harness、Pi；代码评审侧接 Git、GitButler、Jujutsu、Perforce、GitHub、GitLab。核心产品是 Inbox：agent 把问题挂在那里继续干活，你有空再答，**不挂起任何会话**。Apache-2.0。
- **为什么这周会热**：本周新增约 **3,396** stars，上周是 818，**一周涨了 4.2 倍**；总 stars 约 **1.42 万**，1,411 个 fork，205 个未关闭 issue。**v0.29.0 / v0.29.1 于 11 月 19 日发布**——这是本周“发版带动热度”最干净的一个案例。
- **有什么新意**：v0.29.0 把代码评审窗口重做了：双栏 + 文件树 + 图片 diff + minimap，移动/重命名的代码用**语义 diff** 识别，而不是按行对；可以就某条评论和 agent 直接对话，不用重开一轮；大改动可以开“引导式评审”，agent 把 diff 分成章节、按重要性排序。还加了 `plannotator routine` 命令和 `/create-routine` 技能、在设置里把 Inbox 的代码评审做成开关、按 PR/仓库隐藏、视频倍速。**它解决的是评审的入口问题：不是“能不能评”，而是“三十个文件摊在你面前时从哪下手”。**

### 9. [tradermonty/claude-trading-skills](https://github.com/tradermonty/claude-trading-skills)

- **它是做什么的**：面向时间有限的个人投资者的 Claude Skills 工具包：市场复盘、技术图表、经济日历、选股器、交易策略开发、风险与持仓管理、交易日志。立场写得很清楚：**不替你决定买卖**，也不做信号服务，目标是把决策流程结构化。核心是长期投资/ETF/股息，波段交易只做卫星仓。MIT。
- **为什么这周会热**：本周新增约 **3,113** stars，总 stars 约 **7,649**，**1,481 个 fork，fork 率 19.4%——全榜最高**，51 个未关闭 issue。fork 率高在这里的含义和 daily_stock_analysis 那种“fork 即部署”不同：更像是“每人一份自己的参数”，把仓库当模板抄走。最近提交集中在 `exposure-coach`：给板块数据加时效闸门（按 `--as-of` 判断数据是否过期）、只消费规范化的 sector-analyst 报告、对全空的板块斜率显式拒绝而不是静默通过。
- **有什么新意**：它的工程重点不在“多接几个行情源”，而在**数据新鲜度和口径**。金融场景里最危险的失败不是模型算错，而是拿了一份三天前的板块数据当成今天的结论——所以它把 `meta.fresh` 这类生产者自报字段重新按日期校验。这和本周 open-code-review 的“定位漂移”、last30days 的“来源正确性”是同一类问题：**agent 系统里，输入的来源与时间戳必须被当成一等公民。**

### 10. [ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp)

- **它是做什么的**：把 Chrome DevTools 交给 agent 的 MCP server，同时也是 CLI。能力三块：录 trace 并提取可执行的性能洞察（可对照 CrUX 真实用户数据）、网络请求/截图/控制台分析（带 source map 的堆栈）、用 Puppeteer 做可靠自动化（自动等待动作结果）。官方只支持 Chrome 与 Chrome for Testing，默认上传匿名使用统计（可关）。Apache-2.0。
- **为什么这周会热**：本周新增约 **2,795** stars，总 stars 约 **5.87 万**，4,906 个 fork（8.4%），139 个未关闭 issue，**v1.13.0 于 11 月 11 日发布**，抓取当天仍有推送。它和 modern-web-guidance 构成一对：一个负责“写出符合现代 Web 的代码”，一个负责“在真浏览器里证明它确实这样跑”。
- **有什么新意**：v1.13.0 加了 **logpoints**（基于 DevTools 的 BreakpointManager）和**页面级网络 mock / 上游响应 mock**。这两件事把它从“只读观察器”变成“可复现的调试台”：agent 可以先 mock 掉不稳定的第三方接口，再复现失败路径，而不是对着一个偶发 500 猜。修的东西也很实际：配置文件的 UTF-8 BOM、循环引用的 `Error.cause` 链不再无限解析。**给 agent 的调试工具，价值不在于能看到多少，而在于能不能把一次失败变成可重放的实验。**

### 11. [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills)

- **它是做什么的**：Google Stitch（UI 设计生成）的 agent 技能与插件集合，遵循 Agent Skills 开放标准。三个插件包：`stitch-design`（设计向）、`stitch-build`（构建与组件）、`stitch-utilities`（辅助）。支持 Codex 插件市场、Claude Code / Cursor 的 `npx plugins add`、Gemini CLI、Antigravity，OpenCode 需手动装。Apache-2.0。
- **为什么这周会热**：本周新增约 **2,431** stars，总 stars 约 **1.15 万**，1,445 个 fork（12.6%），**只有 27 个未关闭 issue**（每千星 2.3）。仓库的 Release 还停在 5 月的 v1.0，但 11 月 20 日一天合了四条验证相关 PR。热度更像是随 Stitch 本体和“插件市场”这条分发路径一起上来的，而不是某个版本发布——这一点只能从提交与安装方式推断，页面本身没给归因。
- **有什么新意**：那四条 PR 全在**收紧验证**：识别 CSS-first 的 Tailwind v4 配置、拒绝在 React Native 组件里用不支持的 Web 标签、校验 `className` 表达式里硬编码的颜色、把 CI 令牌限制成只读。这暴露了“设计生成 → 代码落地”之间真正的缝：模型生成的 UI 代码在语法上通过、在目标运行时却跑不起来。**技能包的价值不在生成得多漂亮，而在生成之后那一道能挡住错误的检查。**

## 技术趋势分析

#### 趋势一：验证从“评审环节”下移到“工具契约”

上周的结论是“验收成了瓶颈”，本周的进展是**验收被写进了工具本身**。open-code-review 把文件选择、捆绑、规则匹配做成确定性流水线，只把动态决策留给模型；ffmpeg-skill 让每个工具在写文件后 probe 一遍，并用守卫测试覆盖全部 42 个工具；Univer 的 agent 改完内容要过渲染截图与版式 lint；modern-web-guidance 干脆提供 `legacy-scan` 去扫存量代码。

四个项目、四种介质，做法一致：**不再依赖“让模型再检查一遍”，而是让执行器自己产出可核对的证据。** 这是对“同会话自评价值接近于零”那条结论的工程回应——如果评审必须换上下文，那更便宜的办法是让工具在写的时候就留下证据。

#### 趋势二：上下文预算成了产品参数

这周有四个项目在 README 里直接谈 token：open-code-review 宣称同等模型下只用通用 agent 的 **1/9**；modern-web-guidance 用 eval 剪掉“模型已经会”的内容，把指南做成 token-efficient；ffmpeg-skill 的 MCP 默认只暴露 **12/42** 个工具，怕的是工具定义撑爆客户端上下文；astryx 把可选菜单与提示拆成懒加载，缩小初始包体。

一年前大家比的是“支持多少工具、多少数据源”，现在开始比“在同样的上下文里能塞进多少有效信息”。**这个转向意味着技能/工具的评估标准变了：不是能力上限，而是单位 token 的有效动作数。**

#### 趋势三：分发收敛成“npx + MCP 端点”

本周 11 个 AI 项目里，安装方式高度雷同：`npx skills add`（last30days）、`npx modern-web-guidance install`（Chrome）、`npx ffmpeg-skill`（视频）、`npx plugins add`（stitch-skills）、Claude Code 插件市场（plannotator、last30days）、MCP server（chrome-devtools-mcp、ffmpeg-skill、plannotator inbox）。astryx 更彻底：**CLI 每个命令都是 MCP 工具**。

这对写工具的人是坏消息也是好消息：坏消息是“我做了个 skill 仓库”不再稀缺；好消息是**分发层已经标准化，胜负回到工具质量本身**。同时也带来一个新问题——同名的 skill 从不同来源装进来，版本冲突谁负责？本周还没有项目正面回答。

#### 趋势四：协议层三层结构基本定型

MCP 管工具，A2A 管 agent 之间，AG-UI 管 agent 与界面。这周 AG-UI 1.0 冻结、SDK 从 JSON Schema 生成，是三层里最后一块补上的拼图。冻结之后，“事件类型”不再是一个会漂的接口，而是一份可以生成代码的契约。

值得对照的是 open-code-review 和 ffmpeg-skill 的选择：它们没有等协议，而是先把**输入契约**（规则模板、`argparse` 派生的 JSON Schema）做硬。**协议解决的是“怎么连”，契约解决的是“连上之后凭什么相信结果”。** 本周的榜单说明后者更缺。

#### 趋势五：榜单变长、单点变弱，排名越来越不可比

13 个仓库、45,527 星，平均 3,502；上周 11 个、61,501 星，平均 5,591。GitHub 的 Trending 页面长度和入选门槛本身在变，长尾项目（524 星的 HermesEnabler）也能进榜。**这意味着“本周第几名”横向比较的意义在下降，周增绝对值和“它为什么在这周出现”才是可比的。** 本文因此按周增重排，并在每个项目里写清触发点（发版、规范冻结、重新定位、版本窗口）。

## 本周最值得关注的新鲜点

1. **Univer 把“AI office”做成了 SDK 而不是应用。** 同一份快照同时服务浏览器编辑器、后端和 agent，agent 改完还要过截图与版式 lint，草稿在 Worktree 里等人合并——这是本周最完整的“agent 生产 Office 文档”闭环。
2. **open-code-review 敢公布“Recall 更低”的 benchmark。** 50 仓库、200 PR、1,505 个标注问题，承认 Precision 优先、token 1/9、Recall 让步。评审工具愿意公开自己的取舍，比再刷一个 SOTA 更有价值。
3. **ffmpeg-skill 的守卫测试是本周工程质量最高的一处。** 用一段 16:9、5.1、带章节与字幕的片子把所有工具跑一遍，专门抓“章节没重算”“声道丢了不说”“dry-run 报了测量值”这类沉默失败；`input_schema` 从 `argparse` 派生，CI 挡漂移。
4. **AG-UI 1.0 冻结，SDK 由 schema 生成。** 三种语言不再各自漂移，0.x 与 1.0 双向兼容。agent 前端从“每家自己接”进入“按规范接”。
5. **plannotator 一周 4.2 倍增长，靠的是一次评审窗口重做。** 语义 diff、引导式评审、和 agent 直接对话，解决的是“三十个文件从哪看起”。
6. **非 AI 只剩 5.6%，但 sure 证明了另一种可能。** 一个被原团队放弃、烧掉近百万美元的项目，靠社区月度发版活了一年多；1,078 个未关闭 issue 是负担，也是它还活着的证据。

## 结语

这一周没有项目在比模型更聪明。第一名把表格项目重写成 Office SDK，第二名把 Web 最佳实践压缩成能塞进上下文的 3KB，第三名让 agent 去搜“人”而不是“编辑”，第四名把代码评审拆成确定性流水线加模型判断。

如果要挑一条留给下周看，我会选 ffmpeg-skill 的那组守卫测试。它承认了一件很朴素的事：**agent 会静默地做错，而且做错时不报错。** 所以真正需要工程投入的地方，不是让它生成得更花哨，而是在每个写操作后面加一句“你确定吗”，并且这句确认由代码回答，不由模型回答。
